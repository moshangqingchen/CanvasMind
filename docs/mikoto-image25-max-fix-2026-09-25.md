# Image 2.5 质量菜单与最高默认档位修复

MikotoPro「生图（2k4k 高质量）」分组的 GPT Image 2.5 Flare、Sunburst 恢复 `auto / low / medium / high / xhigh / max`，新建或切换型号时默认最高可用档位 `max`。

根因有两层：分组名和 Image 2 的“高质量”描述被误用为 Image 2.5 的质量上限；切换连接时旧缓存写入的 `high` 又被当成用户已保存的选择，异步加载完整目录后没有更新。

修复按当前型号识别分组中的“五档质量”声明，并修复旧的 high-only 目录。明确的档位拒绝、同 Key 实测限制以及 Image 2 固定 high/medium 分组继续生效。新增节点和切换连接/型号产生的质量值标记为自动默认，目录刷新后更新到当前最高可用值；手动选择 lower/auto 后保存为自定义，不会被刷新覆盖。该标记随画布保存，也包含在即时保存恢复日志中。

验证：

- 160 项相关单元测试通过，包括型号隔离、缓存恢复、明确拒绝、实际适配器的六档模拟请求，以及自动默认/手动选择/保存恢复。
- 8 项界面测试通过，包括两个 Image 2 固定分组、两个 Image 2.5 型号，以及三个缩放比例下的供应商/分组/型号真实选择和多连接身份隔离。
- TypeScript 构建、所修改文件 ESLint、打包桌面版启动、模拟生成、保存、重启检查通过。
- Windows 发布工作流加入上述单元测试和两套参数界面测试，失败时阻止进入发布步骤；现有 CI 也会运行这些测试。
- 实际程序读取 90 条连接，81 条可返回缓存目录；74 条提供 max 的型号记录均以 max 为目录默认值，未发现 default=high 的记录。其余 9 条无法读取，不能宣称核验其目录。
- Mikoto 两条实际目录均已恢复六个选项、默认 max。这是参数及模拟请求验收，未新增付费生图，也不把声明改写成供应商实测。

安装备份及回读证据保存在 `.codex-temp/mikoto-max-fix-20260925/`。现有画布、素材、运行记录、核验队列继续使用原数据；重启时既有云任务的状态查询会更新检查时间和请求耗时，不重新提交任务。

最终安装构建为 `2RHAhwQMXiUZPqPgenAM0`。已从实际窗口回读 Sunburst 的完整六档菜单和当前 `max` 选择。安装前后 7 个画布、182 个素材、192 条运行及 192 条节点运行记录保留，13 个供应商核验队列及其暂停状态保留。
