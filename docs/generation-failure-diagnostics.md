# 生图失败原因与扣费信息

生成失败卡片、运行历史的错误详情、结果来源弹窗共用失败诊断，展示失败原因、扣费状态、金额及下一步操作。原始错误、渠道和供应商任务号仍可查看与复制。

运行历史默认展开错误信息，结果来源中的技术详情默认折叠，便于先看结论。结果来源弹窗打开期间保持对应节点挂载，缩小窗口后不会意外关闭；没有已保存图片时也不再显示“当前为第 1 张”。

## 原因分类

- 余额或额度不足。
- 本机网络连接异常：仅在有明确本机连接证据时使用。
- 网络链路异常：连接中断、超时或无法定位具体故障位置。
- 供应商暂无可用账号或容量：与用户账户余额、密钥问题分开。
- 供应商服务异常。
- 密钥或访问权限异常。
- 请求频率或并发超限。
- 请求参数不符合要求。
- 内容审核未通过。
- 本地保存异常：供应商已生成时优先取回原结果。
- 原因待确认：没有足够证据时不猜测责任方。

## 扣费证据

| 状态 | 显示依据 |
| --- | --- |
| 已扣费 | 本次供应商响应或原任务记录明确表示扣费；有明确金额时显示金额与币种/单位 |
| 未扣费 | 本次响应明确表示未扣费，或程序有证据确认生成请求尚未提交 |
| 已退款 | 供应商返回明确退款信息，金额按退款金额展示 |
| 扣费待确认 | 供应商没有提供本次扣费凭据，或证据矛盾、结果不明 |

没有金额时显示“未提供”；有金额但没有币种时明确提示币种/单位未提供，不默认人民币，也不根据模型报价计算实际扣费。账户余额变化、HTTP 错误状态、没有供应商任务号、生成失败，都不单独证明本次请求未扣费。查询或下载失败也不能推断原生成任务免费。

`pending`、`processing` 等待确认状态，以及明确的 `estimated`、`approximate` 估价内容不会当作已完成账务。不同币种不自行换算，站点明确给出 `QUOTA` 时显示原始额度单位。

保留原任务返回的有效账务证据，后续查询没有费用字段时不抹去旧证据。分类与费用经过字段白名单后返回界面，不公开完整供应商响应或凭据。证据更新时，即使错误文案相同，画布也会更新费用并保存。

这项功能不改变付费生成的重试策略，不自动创建新的生图请求，也不把历史记录中缺失的扣费信息补成“未扣费”。不支持单次账务凭据的供应商仍需在其后台核对。
