## App 中提供的档位

| 分组 | GPT Image 2 | GPT Image 2.5、Flare、Sunburst |
| --- | --- | --- |
| B1、B2 | 1K、2K、4K | 1K、2K、4K；4K 请求实际返回 3584×2016，按接近的尺寸归为 4K |
| B3 | 1K、2K | 1K、2K |
| B4 | 1K、2K、4K | 1K、2K、4K |

- 档位按用户要求就近归类：在相同比例下，实际尺寸更接近 2K 预设就归 2K，更接近 4K 预设就归 4K；不要求精确匹配原生 4K。`3584x2016` 更接近 4K，因此 B1、B2 的普通 2.5、Flare 和 Sunburst 恢复 4K 选项，同时继续展示实际像素。归类调整沿用已有测试，没有追加付费请求。
- GPT Image 2 在 B1、B2、B4 的 `3840x2160` 请求均返回相同目标像素。2.5 系列只有 B4 精确匹配目标；B1、B2 的普通 2.5、Flare 和 Sunburst 都发生缩小，归为接近的 4K 档。B3 原文明确不支持 4K；未为它发送超出说明的 4K 测试。
- B1、B2 的部分 1K 方图请求 `1024x1024` 返回 `1254x1254`。部分 2.5 / Flare / Sunburst 的 `1536x2720` 请求返回 `1136x2048`；部分宽屏请求也会轻微调整。参数中的像素为请求值，不保证每次精确。
- K 档位沿用 App 的像素预算预设；供应商账单对非方图的档位命名可能不同，例如 `1536x2720` 会被后台记录为 4K。当前四个分组各尺寸单价相同；不把后台档位文字当成图片像素证据。
- 提供 11 种常用比例及自定义宽高。已经生成验证的具体尺寸有记录；其余组合明确标为“比例预设”，不宣称所有档位、比例和质量的笛卡尔积都已测试。

## 请求质量

- GPT Image 2 / 2.5：测试了 `auto / low / medium / high / xhigh / max`。
- B3 的 GPT Image 2：`low` 请求 `1184x880`、`auto` 请求 `880x1184` 连接中断。不能断言质量值不支持，也不能当成已验证；本轮不列这两项。该分组 GPT Image 2.5 的对应测试成功。
- Flare / Sunburst：B3、B4 只实测 `high`；B1、B2 补测了 `max`，仅列出这两个可提交值。额外六次测试确认 B1、B2 的普通 2.5、Flare、Sunburst 在 `high`、`max` 下都把 `3840x2160` 缩成 `3584x2016`，按就近规则提供 4K 档位。
- 无效质量值 `unsupported-quality-probe` 也能出图。GPT Image 2 的部分 low、auto、high、xhigh、max 请求都在响应中返回 `quality: medium`。因此界面标为 **请求质量**，并提示“参数可提交不代表存在六种独立画质”。2.5 型号通常不返回质量字段，不能假造其最终质量。

## 实现与证据

能力严格按 HTTPS API 地址、分组、模型 ID 匹配；不会套用给其他自定义供应商、智能体连接、已停用供应商或被拒绝的模型。保留模型已有操作，不因生图成功额外声明图像编辑已验证。

自动比例先读取提示词，再参考图，并保留选择的 K 档位。过往保存的精确尺寸优先；未提供的档位以及超过当前验证范围的尺寸会在本地拒绝，避免无意付费。

[逐请求测试与扣费记录](monster-image-verification-2026-09-20.json) 只保存非敏感测试参数、实际像素、质量回显、费用和图片 SHA-256，不含账号、密码、密钥或登录令牌。每一个暴露的型号、K 档位和质量值都由回归测试核对这份记录中的成功图片证据。
