# 项目维护

当前交付目标是 Windows 桌面 App。`apps/desktop` 是桌面外壳，`apps/desktop/renderer` 是 App 内嵌界面和本地 API，都属于桌面 App，不存在独立网站工程。

## 目录用途

| 目录                                                                             | 用途与保留规则                                                                                           |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `apps/desktop/src`、`apps/desktop/renderer`、`packages`                          | 当前功能源码与测试                                                                                       |
| `apps/cloud-generation`                                                          | 可选 Cloudflare 图像生成网关源码；供桌面云端生图设置使用，不是独立网页应用，也不随桌面安装包启动         |
| `apps/desktop/stage`、`apps/desktop/dist`                                        | 已准备的桌面运行资源；普通清理保留                                                                       |
| `apps/desktop/renderer/.next-desktop`                                            | 最近的桌面界面构建；普通清理保留                                                                         |
| `apps/desktop/release`                                                           | 当前版本安装包、更新文件与打包验证产物；旧包核对版本后单独清理                                           |
| `%LOCALAPPDATA%/Programs/SuperCanvas`                                            | 本机正式安装目录；日常使用与 Dock 指向这里，不在仓库中维护安装副本                                       |
| `.codex-temp`                                                                    | 历史诊断、测试和素材验证；只自动清理已知测试部署中的构建、日志和重复依赖                                 |
| `.codex-logs`、`output`                                                          | 原请求、账单、安装与目录读回、修复事务和原始生成素材；普通及深度清理均保留，不按日志或临时输出整目录删除 |
| `backups`、`项目`、`apps/desktop/renderer/data`、`apps/desktop/renderer/storage` | 历史数据与恢复资料；不列入构建清理                                                                       |
| `%LOCALAPPDATA%/SuperCanvasDesktop/profile`                                      | 当前 App 的画布、素材、连接和历史；不在仓库清理范围内                                                    |

## 日常清理

先结束源码开发服务和测试，再执行：

```powershell
pnpm clean:check  # 只预览清单和可回收空间
pnpm clean        # 执行普通清理，保留当前桌面启动资源
pnpm start        # 继续启动已经构建好的桌面版
```

要从依赖开始重建，才使用：

```powershell
pnpm clean:deep -- --dry-run
pnpm clean:deep
pnpm install --frozen-lockfile
pnpm dev
```

清理仅操作工作区内的可重建路径。它逐层检查路径边界，拒绝穿过符号链接或 Windows junction，删除构建目录时也不跟随内部链接，并在实际删除每个目录前再次核对边界。Git 跟踪文件及其所在目录始终保留，即使名称与构建缓存匹配；执行时重新读取 Git 索引，防止旧清单删除后来纳入版本管理的文件，索引读取失败则停止。`pnpm test:maintenance` 验证素材、备份、安装副本、跟踪源码和目录链接的保护边界，CI 同样运行这些测试。

`.codex-logs` 虽然名称含 logs，也包含不可重建的原始请求、未知扣费追查、安装器身份与数据库修复计划/回执；`output/imagegen` 保存供应商返回的原文件。两者不属于可直接删除的开发日志，普通清理和 `--deep` 都不会删除，也没有跳过这条保护的清理参数。需要整理其中真正可重建的文件时，先逐项核实来源、引用和独立保留副本，再单独处理；不要使用 `git clean -fdx` 代替项目清理。Git 忽略规则只防误提交，不是删除授权。

普通清理也包含 `.ui-*-results` 形式的历史界面测试输出；只识别这个明确的产物命名，不处理其他 `.ui-*` 隐藏目录。

执行清理或再次运行 E2E 前，先核对测试输出中的截图、视频和 trace 是否仍是唯一的验收证据。需要保留的证据应归档到 `docs/audits`、`docs/private-evidence` 或明确的 `.codex-temp` 审计目录，逐文件校验长度与 SHA256 并记录原路径；确认归档完整后，才清理原测试输出。`test-results*` 是可覆盖的测试目录，清理脚本不会判断其中的证据是否已有副本。归档搬移量与真正删除的可重建文件大小分别统计，不能把仍保留的证据算作节省空间。

## 质量检查与测试隔离

`pnpm typecheck` 会先构建运行服务与导演引擎的共享依赖，支持干净检出。`pnpm test` 只收集各包源码中的单元测试，不扫描 `dist` 或 Next.js standalone 产物。`pnpm test:maintenance` 同时运行清理边界、素材 GC 和供应商目录检查器的回归测试；维护测试使用项目 `.codex-temp` 内的独立目录，结束时仅清理自身创建的测试资料。

构建后运行 `pnpm --filter @super-canvas/desktop-ui e2e`。自动启动的测试服务使用项目 `.codex-temp` 内每次独立的目录，隔离数据库、素材、项目归档、恢复文件和素材通道配置；结束时先停止服务，再清理该临时目录。维护和 E2E 测试均拒绝将这个目录重定向到项目外的符号链接或 Windows junction。显式设置 `PLAYWRIGHT_BASE_URL` 则使用调用方指定的服务，由调用方负责其数据隔离。不要指向正在使用的个人资料库。

画布性能数据和 CPU profile 写入 Playwright 的当前测试输出目录。历史遗留的 `apps/desktop/renderer/项目` 已加入 Git 与打包忽略规则，保留现有文件以供核对，不作为源码或安装包内容。

旧版本安装副本和历史安装包不做自动按时间删除。先确认桌面快捷方式、卸载注册和运行进程都指向当前版本，且旧目录没有用户资料，再单独删除明确的旧副本。

2026-09-29 已按上述核对流程整理本地工作区，删除不再使用的旧程序副本和历史安装包，保留当前 0.2.43 安装包、更新文件和开发启动资源。以后不要再向 `apps/超级画布桌面版*` 复制日常使用的程序，避免启动旧版本和重复占用空间。历史诊断目录可能同时含程序副本、数据库快照和原始生成素材，不能直接删除整个 `.codex-temp` 或 `backups`；程序副本与资料必须分别检查。具体清单及保留范围见[本地工作区整理记录](workspace-cleanup-2026-09-29.md)。

旧独立网页版及其 Docker、Worker、PostgreSQL、S3、网页更新与守护脚本已移除。当前 `apps/cloud-generation` 是另行部署的可选图像生成网关，仍被桌面设置、供应商连接和运行时提交/恢复使用，应保留。旧网页版资料仅作为迁移备份保存，不参与构建；导入时选择包含 data、storage 和原加密配置的目录。

不把 `gc:storage:apply` 用于日常整理，它处理实际素材，需要独立检查引用和备份。图片修复、供应商协议和历史运行记录属于功能与数据，不按“文件较旧”删除。

## 退出进度与诊断

退出与安装更新使用四个阶段：保存已打开界面的内容、检查后台状态、等待已确认的任务或写入、关闭本地服务。检查尚未完成时，计数保持未知，不按零任务处理；没有已确认的任务时，界面不显示“正在等待任务完成”。生成任务、供应商核验和后台写入分别展示，核验不重复计入生成数量。安装更新与普通退出使用不同措辞。

保存、检查和等待阶段仍可通过“返回软件”调用现有安全取消流程。真正进入关闭阶段后停止提供取消操作。旧的 `onDraining` 桥继续可用，缺少阶段事件时只显示通用的“正在准备退出”。渲染器保存确认与后台请求原有的 30 秒、15 秒超时不因进度显示而放宽；检查错误在界面显示，并保留桌面错误提示。

退出前的最后一次后台读回也必须确认 `draining: true`，且运行、核验、写入三个计数均为非负整数，核验数不能超过包含它的运行总数。缺失、无效或不一致的状态中止退出并报告错误；最后读回重新发现任务或写入时继续等待，不提前停止轮询或更新检查。轮询按次执行，生命周期请求按顺序完成；取消等待对应的恢复请求结束后才允许重新退出，旧尝试和已更换后台实例的响应不能关闭当前软件。

2026-10-22 源码安全复核通过：桌面 Node 回归 163 项通过、1 项既有跳过，渲染器类型检查与差异格式检查通过。新增回归覆盖最后读回出现新任务/写入、未知计数、慢请求与轮询重叠、取消与重新退出顺序、旧响应及后台实例变化。这里记录源码证据；安装包运行、真实用户现场和供应商收费生成须分别验收，不用单元测试代替现场结论。

正式安装版的阶段诊断写入 `%LOCALAPPDATA%/SuperCanvasDesktop/logs/desktop.log`，以 `exit` 开头。每次退出记录尝试编号、阶段、是否安装更新和已读取的活动计数，以及保存确认、失败、取消、关闭完成事件；相同计数的 1.5 秒轮询不重复记录。日志不包含任务正文、Key、来源 URL 或原错误正文，关闭完成日志先落盘再退出。生命周期接口的 `activeRuns` 包含 `activeVerifications`；核对界面生成数量时须减去核验数量，不能把两者相加。

2026-10-22 已确认旧通用提示会在无任务时错误声称等待任务，该提示问题已修复。现场此前长时间等待的实际阻塞原因尚未确认；只读核对未发现当时存在运行中的生成或供应商核验，但不能据此推断后台写入或退出流程一定空闲。后续复现应保留该次退出前后的阶段日志、界面显示和时间，依据最后已完成的阶段继续定位，不将这次提示和诊断改动描述为已经修复现场卡住根因。
