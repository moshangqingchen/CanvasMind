# 供应商完整接入与持续复查规则

更新：2026-10-09。来自用户本次明确要求，适用于本项目所有已有及新增供应商、账号、Key、分组和型号。它补充并优先于旧资料中仅检查图片、只读目录或留待接口核验的范围限制；原有不伪造证据、不重复收费、保护历史资料和用户选择的规则继续执行。

**视频收费边界（用户本日纠正，优先于下文“最小核验”措辞）：不要付费验证视频模型。** “完整检测供应商”不构成收费视频请求授权。视频默认通过免费官方资料、当前目录/schema、代码和界面回归、已有任务/原视频/账单完成核查；没有已有证据的真实生成或下载验证明确标为未完成。新增收费视频生成、编辑或续写必须由用户另行明确授权。本轮后续所有新增收费验证均已停止；已提交任务仅免费查询原任务与账单，不自动重发或充值。

## 用户要求的结果

每次供应商检查或新增接入，都要完整检测并完成实际接入：图片模型和视频模型都包括在内，能取得并有当前账户使用条件的分组与型号全部接上。每个型号有正确接口、参数、结果获取方式和它自己的正确价格。新模型、新分组以及已有分组更名、换组、参数、接口或价格变化，要检测出来并一起更新。

工作不能停在目录列表、通用的“协议未验证”、临时硬编码一条价格或待办建议。缺项必须继续查官方资料、实际页面入口、例子、schema 与适用的原有测试，再完成需要的程序修复和必要验证。接口和报价来自证据，不能通过放开开关或编造价格实现表面完成。

## 一、冻结范围与收集资料

1. 读取当前实际资料，记录供应商来源、当前账号、有效及失败的连接、官方分组编号和名称、每个 Key 的可见完整型号。
2. 同时读取官网广场、登录后的分组/渠道价格、通知、型号专属文档、API 示例和免费能力/schema。读取页面真实使用的接口；SPA 首页存在不等于技术正文已读，匿名入口失败不等于已登录页面无资料。
3. 分别记录官网可选范围、Key 实际可见范围、已接入范围和已有实测范围。广场的媒体输出与理解/多模态输入分别判断；理解视频不等于能生成视频。
4. 逐来源保存采样时间、HTTP 状态、数据或正文哈希、型号/组匹配依据；不在报告中写入 Key、密码、Cookie、token 或带签名的素材链接。

### 图片分辨率、尺寸与质量

用户明确要求：接入的图片型号必须清楚支持哪些档位、每档怎样确定尺寸以及有哪些限制，并落实到实际控件、调用与报价。每个供应商、实际 Key 分组、完整型号及文生图/编辑操作分别记录：

1. **分辨率档位及定义。** 读取该型号真实支持的全部档位、接口原始值和默认值；1K、2K、4K 等仅作标签示例，不能预设所有型号都支持，也不能假定同名档位在不同供应商、比例或型号下等于同一宽高。
2. **比例与实际像素尺寸。** 给出每档合法比例对应的宽 × 高，或供应商明确的计算规则、范围与取整方式。区分输出尺寸、参考图及蒙版输入尺寸与各自限制。查清省略尺寸、默认档、auto 的行为，以及编辑是否继承参考图尺寸、如何裁剪/补边/缩放。若输出是动态、自适应或原图比例，保留其真实语义和条件；资料未给定固定像素时不编造换算表，继续查证需要的事实，实测只代表对应参数的样本。
3. **自定义尺寸限制。** 核对是否可自定义宽高、最小/最大边长、像素或面积上限、步长/倍数、宽高比范围及组合约束。区分固定枚举与可输入范围；不支持任意宽高的接口不得显示为任意输入。
4. **质量及功能组合。** 分清分辨率、质量、压缩和格式，不能把“高清/高质量”自动当作更高像素档位。核对不同档位与参考图、编辑、蒙版、透明背景、输出数量等是否存在限制；原生输出与供应商提供的放大输出分别说明，不把后期放大算成原生能力。
5. **请求与价格对应。** 明确 size、resolution、image_size、aspect_ratio、width/height 等实际字段及精确枚举、大小写、必填项和默认值，不假定所有字段均适用。档位、比例、宽高或质量改变时，控件、请求和报价同步采用当前合法组合；禁止把不同档位套成同一固定价格，除非有该型号的明确统一计费依据。
6. **界面与刷新验收。** 界面清楚显示当前档位、比例、可确定的像素尺寸及限制。切换型号/分组后只提供实际支持的选项，对无效组合明确提示，不静默降档或替换用户选择；合法的已保存参数应保留。自动/手动刷新、重新打开及重启后检查选项、联动、请求映射和价格一致。
7. **输出验证。** 复用有效的已归档结果，必要时对仍缺证据的分支做最小实测；保留用户选择与实际提交字段，解码读取实际下载原文件的像素宽高，多张结果逐张核对，并记录供应商降档、取整或改变比例的差异。缩略图、菜单标签、请求参数或 HTTP 200 不能证明输出尺寸正确，也不能用单张样本推断所有比例和档位。不能为核对参数表重复购买已确定的事实。

在逐型号覆盖表中保存上述档位/尺寸规则、适用条件、来源和验证范围；只登记型号名称及价格不算完成图片接入。

### 图片参数的统一展示格式

2026-10-09 用户通过参数面板截图澄清：“图片格式”此处指参数在界面中的清楚展示方式。后续图片型号接入与刷新按该布局验收，文件编码要求不能代替这一展示要求：

| 展示顺序 | 界面要求 |
| --- | --- |
| 型号 | 清楚显示型号名称和完整 ID，以及有依据的功能标记 |
| 分辨率档位 | 用分段按钮清楚排列当前型号支持的档位，例如“自动 / 1K / 2K / 4K”，突出选中项 |
| 比例与尺寸组合 | 选项直接写成“档位 · 比例 · 宽 × 高”，例如截图中的“4K · 1:1 · 2880 × 2880”，不用打开其他说明才能看见对应像素 |
| 宽高 | W / H 分别显示实际像素；支持自定义才允许编辑，只支持固定尺寸时显示选定值及合法选项 |
| 尺寸限制 | 在尺寸控件附近说明当前型号的倍数对齐、范围或总像素限制；供应商强制限制不能作为可关闭选项 |
| 质量 | 独立展示清楚的质量选项，例如该型号支持时显示“最高（max）”，不能与分辨率档位混用 |
| 生成模式及其他参数 | 按实际能力继续分项展示生成/编辑模式、输出数量、透明等，不混入尺寸选项或隐藏必要条件 |
| 对应报价 | 随当前供应商、实际分组、型号、档位、质量等计价条件更新，清楚显示单位和适用条件 |

截图是展示结构示例，不是所有型号共享的能力或数值表。不能据此认定所有型号都有 4K、4K 正方形都是 2880 × 2880、都要求 16 倍数对齐或都支持 max。每项内容读取该型号的真实规则；自动/动态尺寸没有固定像素时如实显示其含义，不编造确定宽高。

档位、比例组合、W/H、质量及报价必须联动，提交字段与界面一致；不允许下拉框显示一组尺寸而 W/H 或实际请求采用另一组。自定义宽高不再符合预设组合时明确显示“自定义”，不能保留不匹配的预设标签。接入、刷新、切换及重启后主动按该格式检查可读性和一致性，保留合法的用户选择。

### 图片输入、输出格式与透明背景

图片格式同样是逐供应商、实际分组、完整型号和生成/编辑操作的接入验收项，不能所有型号共用一份未经核对的格式列表：

1. **输入与输出分别查清。** 分别记录参考图、蒙版支持的真实编码格式、文件大小/数量及透明通道要求，以及生成结果支持的格式、默认格式和省略/auto 的行为。PNG、JPEG、WebP 等只是核对示例，只有该接口实际支持的格式才可选择；扩展名别名与接口枚举分别处理。确认静态/动图及多帧输入的支持和处理规则；蒙版还需核对黑白、灰度或 alpha 的编辑区域语义，以及与参考图的尺寸、方向和对齐要求。
2. **格式字段与传输方式分开。** 核对 output_format 或该接口对应的真实字段、精确枚举、大小写及适用条件；URL、base64、data URL、二进制是传输/返回形式，不等于 PNG/JPEG/WebP 编码。不能因为能返回 base64 就声称支持任意图片格式，也不能显示接口忽略的格式选项。
3. **透明、压缩与质量。** 查清透明背景/alpha 的支持范围和请求字段，核对与输出格式、编辑、尺寸及质量的合法组合。JPEG 不保留 alpha，透明输出使用供应商支持且能够保留 alpha 的格式；不能静默铺底转 JPEG，也不能把画有棋盘格的图片当作透明图。分别记录有损/无损、压缩参数的范围和默认值；压缩质量、生成质量与分辨率不能混为一项。收费有差异时保存对应条件与依据。
4. **原文件验证。** 保存用户选择和实际提交字段，检查下载原文件的签名/编码并成功解码，核对真实格式、MIME、后缀、像素宽高和透明通道；需要透明的结果还要检查实际透明像素。不能只看 URL 后缀、Content-Type 或预览外观，不能将错误 JSON/HTML 存成图片。多张结果分别核对，对格式回退、MIME/后缀错配或透明丢失记录并处理，不能冒充符合请求。
5. **预览与原图保存。** 保留供应商原文件供归档和下载，预览缩略图与原文件分别处理，不静默重编码、压缩、铺底或仅改后缀伪装格式。供应商只支持一种输出时如实显示；用户明确要求的另存转换与供应商原生能力分别标识，并遵守项目的图片生成/编辑工具要求。
6. **全链路一致。** 界面格式、透明和压缩选项必须映射到合法请求，保存/恢复、刷新、切换和重启后仍与当前型号规则一致；预览和下载不得丢失已取得的原图能力。覆盖表记录格式规则、限制、来源及验证范围，先复用有效原文件证据，仍缺关键事实时再最小核验，不重复购买已确定的事实。

### 视频完整接入与参数展示

用户明确要求视频也完整按照当前供应商的信息接入。对每个实际分组、完整型号和操作模式分别查模型广场、分组说明、通知、专属文档、API 示例及 schema；记录来源、时间与适用条件。不能把原厂、其他供应商、相近型号或通用视频模板的能力直接套过来。

1. **完整模式与能力。** 逐项确认文生视频、图生视频、首尾帧、多参考素材、视频编辑/续写、音频驱动及供应商公布的其他模式；只对真实支持的模式提供入口，并把当前账户可用的模式实际接通。区分参考图、首帧、尾帧、主体参考、参考视频及音频各自的角色、数量和组合要求；能接收某种素材不等于支持所有对应模式。
2. **分辨率、比例与质量。** 核对全部合法档位、对应比例和实际像素宽高或供应商明确的计算规则、默认值、auto 行为、自定义范围及步长。原生分辨率与供应商放大输出分别记录；质量、速度/标准模式及其他等级按实际字段映射，不能仅按名称推断能力。帧率查清是否固定、自动或可选及合法取值，不给固定帧率接口添加无效控件。
3. **时长与声音。** 核对时长是固定枚举、连续范围还是按步长选择，及最短/最长、默认、自动或跟随输入的含义；记录不同模式、档位、声音与参考素材下的组合限制。原生生成音频、输入音频驱动、保留源音轨及静音分别核对；不能用后期配音冒充原生音画同步，不能给不支持声音开关的接口展示无效开关。
4. **输入素材与字段。** 查清图片、视频、音频的上传方式、素材 ID/URL 使用规则、鉴权、有效期、真实格式/编码、大小、尺寸、帧率、时长、数量及合计限制。核对首尾帧顺序、素材角色、裁剪/缩放行为及模式必填条件；种子、镜头、运动、负面提示等供应商提供的可用参数，也要查清字段、类型、枚举、默认值与依赖条件并接入，不能只接一个 prompt。
5. **完整任务链路。** 实现正确的上传、生成提交、同步/异步返回、任务编号、排队/运行/成功/失败状态、查询/回调、轮询与超时、原任务恢复、结果字段、下载鉴权和链接有效期。取消、幂等及结果链接刷新按供应商实际支持处理。提交成功不等于生成完成；超时或响应丢失先追查原任务及扣费，不能盲目重发；刷新、重启和分组更名不得丢失正在执行的任务。
6. **按当前组合报价。** 价格绑定同一供应商、稳定分组身份、完整型号与模式，核对每次/每秒/Token 等单位、币种、倍率，以及分辨率、质量、速度档、声音、参考图/视频/音频、输入与输出时长或用量的计费条件。查清最低收费、时长取整与分段规则；只有依据充分才能计算当前组合总价，估算与实扣分开。不能把按次价当每秒价、把起步价当任意时长总价，或把一次扣费套给全部组合；缺公布价时按同请求/任务核对实扣。
7. **清晰且联动的界面。** 按“模式 → 时长 → 分辨率档位/比例/可确定的像素尺寸 → 质量/帧率/声音等适用选项 → 素材要求与对应报价”分项展示；只有当前模式支持的选项才可选。固定时长枚举不得伪装成任意秒数滑条，模式变化同步更新合法参数、素材要求和报价。显示值、保存值和实际提交值一致，保留合法用户选择，无效组合明确提示，不能静默改成另一模式、尺寸或时长。
8. **真实结果与持续验收。** 获取并保留供应商视频原文件，核对真实容器/编码、MIME/后缀、可解码与可播放性、实际宽高/比例、时长、帧率及音轨；有声请求还需核验实际声音，不能仅凭存在音轨认定有声。预览封面、可访问链接、HTTP 200 或成功状态不能代替原视频验证。复用适用的已有实测，仍缺关键事实时最小核验，记录请求字段、任务、结果和扣费证据，不重复购买已确定的事实。刷新发现新增模式或参数、接口、计价变化时一起更新目录、控件、调用、报价和缓存，并复查切换与重启后的结果。

素材链接有效期要覆盖供应商取用素材与任务恢复所需时间，不能只验证提交瞬间可访问。任务受理、生成完成、原视频可下载播放、账单落账分别确认；失败或取消不代表未扣费或已退款，需核对对应请求的实际账目。

逐供应商/分组/型号覆盖表还需列出每种视频模式及其素材、参数、接口、报价来源与验证范围。目录可见、代码接入、安装版界面可用和真实收费生成成功分别记录；有程序漏项继续修复，真实账户或上游阻碍按第五节留存具体证据并完成其余工作。

## 三、正确报价

- 每条价格绑定供应商当前来源、稳定分组身份、完整型号、适用的渠道和参数条件。数字分组编号相同的改名保留归属，不同编号即使同名也不共享价格。
- 记录原始金额、币种、计费单位、站点倍率与价格来源，按供应商规则恰好应用倍率一次。充值折扣、美元/人民币换算和账面额度各自处理，不互相冒充。
- 分辨率、质量、时长、音频、参考视频、输入/输出 Token、上下文、缓存、时段等影响收费时，保留完整计价条件，界面选择参数后显示对应报价。
- 有明确型号价优先用型号价；只有分组说明价也要显示并标注说明参考。文字未注明币种时保留原文，不擅自构造可用于总价的币种。
- 查不到公布价时读取同一来源/分组/型号的成功测试扣费，精确关联请求/任务，显示本次参数与“生成实测”；一次实际用量费用不能成为所有参数的固定每张价。
- 当前读取失败保留同一身份的最后有效报价并注明历史时间。局部价格目录失败不能覆盖另一来源当前已取得的价格；有价格却显示未取得，应作为程序缺陷修复。
- 真实扣费与公布价不一致时同时记录并核查原因，修正倍率、单位、参数条件或实际渠道匹配；不静默改成零费用或最低档价。

## 四、更新与既有资料同步

检测供应商、分组与型号的新增/删除、更名、官方 ID/别名/Key 绑定变化，以及文档、接口、参数和价格变化。同步更新供应商目录、对应连接、可用型号、接口适配、参数定义、报价和模型菜单缓存。

新组有现有可用 Key 就复用；需要新增 Key 才能完成用户要求的已开放分组接入时，按用户授权及对应账号能力创建并绑定正确分组。不能把其他分组的 Key 权限移植过来。暂时空目录或读取失败保留历史，不伪装为供应商删除了全部型号。

保护原连接 ID、画布引用、用户手选参数、已有任务、素材和费用记录。更名不能引发重复连接、丢失原能力或重复付费测试。已经提交的任务继续查询原任务，不因更新或改名重发。

## 五、完整验证与真实阻碍

先免费读取和核对，复用仍然适用的完整文档与真实测试，补测仍缺的关键事实。图片通常一个合法尺寸/最高合法质量、一张结果即可验证对应提交分支；视频按当前型号的真实合法参数验证需要的生成、查询与下载分支。不为证明菜单逐个购买全部比例或参数笛卡尔组合。

程序逻辑使用隔离资料、模拟契约和界面回归测试；真实提交、媒体下载与账单核对分别记为真实证据。HTTP 200、目录可见、参数菜单或模拟测试不能写成真实生成成功。

认证失效、账户无此权限、余额不足、上游缺号等必须给出精确来源、分组、型号、HTTP/供应商错误和下一步需要的账户条件，继续完成其他可做项目。供应商不公开的信息不能编造，但不能只留下笼统“协议未验证”而结束探索。已付费失败、任务/费用不明时先追查原请求与账单，避免重复购买。

## 六、验收与项目记录

最终保存逐供应商、逐分组、逐完整型号覆盖表，至少包含：当前可见/已接入、图片或视频操作、提交/查询/下载合同、完整参数、对应报价/条件/来源、已有或本轮真实验证，以及具体外部阻碍。

确认新旧目录与缓存都应用修复，运行变更相关回归、类型与静态检查、生产构建和需要的界面/打包检查。涉及实际桌面更新时正常保存退出并备份，更新后从安装程序读回供应商、型号、参数与价格并实际检查模型菜单。报告明确区分源码验证、安装版 API 读回、安装版界面验收和真实收费任务，不能互相代替。

完成清单要以实际证据为准；仍有本程序可以解决的接口或报价漏项，继续处理到完成后再交付。

## 七、防止重复漏检的交付条件

2026-10-09 用户再次明确：不能每次接入和刷新都等用户发现问题后再改。这是本项目的长期执行要求，不依赖用户重复提醒。每次开始先读本规则，交付前主动逐项复核：

1. **完整读取与逐层对照。** 对照官网广场、当前 Key 的通用目录及图片/视频原生目录、schema；按供应商来源、官方分组身份和完整型号核对实际返回、保存记录、普通/刷新接口响应和界面列表。一个入口成功或失败都不能代表其他入口；上游已有而程序没显示，先查读取、映射、持久化、缓存和界面状态。
2. **报价与实际身份一致。** 核对 Key 实际绑定分组及完整计价条件，菜单显示的价格必须能回溯到同一身份的官方资料或同请求实扣。分组改名保留稳定编号，无官方别名映射不借价；价格局部失败不抹掉有效报价。
3. **相同内容也更新确认状态。** 保留有针对性的回归：型号和报价完全相同，但扫描从局部、过期或失败变成成功且完整时，菜单头部、对照数量和可选状态必须更新。状态变化不能被模型内容相等的判断吞掉，也不能通过删除提示掩盖错误。
4. **刷新与缓存路径一致。** 核对自动刷新、手动扫描、重新打开菜单、切换供应商/分组和重启后的型号、参数、价格、确认状态。新扫描使旧缓存失效，晚到旧响应不能覆盖新扫描；确认现有画布引用、用户选定参数、已有任务和费用记录得到保留。
5. **实际安装版界面验收。** 桌面升级后，在不打断用户操作和运行任务的前提下，实际打开对应供应商、分组、模型菜单，核对报价、参数、确认状态和可选性。分别记录源码测试、安装版 API 读回、安装版界面检查、真实收费生成；HTTP 200、后台读回或模拟界面测试不能替代安装版界面证据。若暂时无法操作界面，明确保留尚未完成的这一项，不声称界面已验证。
6. **自行复查后交付。** 每次发现内部漏接、漏读、缓存或显示缺陷，修复实际数据链路并补充能复现该缺陷的回归，再按清单复核。不得把已知内部缺项推给用户再次提出；真实认证、权限、余额或上游阻碍则按第五节记录精确证据，继续完成其余工作。
7. **用途不能掩盖媒体漏接。** 全量审计包含 `usage=agent` 的当前 Key 媒体目录。逐完整型号确认同供应商来源、同官方稳定分组已有可用画布连接；其他分组同名型号不算覆盖。只有智能体连接时保留原用途、连接 ID 和 Key，优先复用该 Key 补齐同组媒体接入，不重复创建上游 Key，也不因审计触发自动收费。型号名称、图片输入或计费单位本身不能证明图片输出；官网实际媒体入口、当前目录/schema 与计费条件分别留证。

上述验收条件同时适用于现有和新接入供应商，不能只保留某一家供应商的临时修补。
