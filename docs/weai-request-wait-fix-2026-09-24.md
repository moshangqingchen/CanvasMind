# We-AI 生图等待时长修复

日期：2026-09-24。

## 发现与限制

新导入的 Image2.5 分组使用 `provider=openai`，因此走通用 OpenAI 图片适配器：旧默认提交上限只有 120 秒。We-AI 专用适配器已有 30 分钟等待和 TCP keepalive，但新分组没有复用这些传输设置。当前连接未显式覆盖等待时间，实际程序没有配置 HTTP 代理环境变量；后续排查确认系统存在 FlClash TUN，不能据此认为请求直连。

供应商 [生图接入指南](https://docs.we-ai.cc/guides/image-generation.html) 明确建议客户端和中转站均设为 30 分钟；[桌面工具说明](https://docs.we-ai.cc/guides/image-playground-desktop.html) 也说明单次请求最长等待 30 分钟。本次仅采用接口事实，不采用网页中的操作建议替代用户流程。

此前 08:34:07 的请求在约 110 秒发生 `UND_ERR_SOCKET`，早于 120 秒本地截止时间。因此这是独立的连接断开证据，不能把它直接判定为本地超时，也不能保证延长时间能解决远端或中间网络主动断开。供应商生图文档说明同步返回 base64、不保存生成结果，当前文档未提供这条 Images 接口断线后按任务编号取回结果的方式。

## 修改

- 精确按 We-AI 域名及其子域名识别传输，OpenAI 兼容的新增生图、编辑请求默认同样等待 30 分钟。
- 复用现有 TCP keepalive 传输，保留当前 OpenAI 请求字段、最高质量、尺寸和参考图，不切换成会过滤参数的旧专用协议。
- 使用 HTTP 代理时，底层响应头和响应体等待同样设为 30 分钟，避免底层默认 5 分钟先结束。
- 显式连接/适配器等待配置仍优先。仅供应商标签相似、伪装域名或其他供应商不会获得这一专用规则。
- 原连接还在等待时继续接收响应；实际断连或截止时保留不明结果，不自动重新提交，不虚构已断开的连接仍在工作。
