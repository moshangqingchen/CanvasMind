# 画布缺陷修复与精致动效优化 · 0.2.23

## 实现范围

- 生成 POST 前持久化提交记录，以原请求编号恢复未确认任务。断网、刷新、关页后核对已有任务；结果不明时不会自动重新生成。本地记录无法写入时阻止提交。
- 保存状态与运行任务分别显示；保存失败可重试，版本冲突保留处理入口。
- 移出运行结果只隐藏卡片，后台任务继续，完成结果保留在历史。隐藏标记随画布保存。取消任务是独立操作。
- 永久删除历史素材时同时清理撤销、重做中的失效引用；普通移出仍可撤销。
- 输入框内 Ctrl+S 保存最新编辑；Ctrl+Enter 运行当前节点；Ctrl+Shift+Enter 运行下游；中文组词不触发生成。恢复 Ctrl 连线多选、取消选择及批量删除。
- 模型名称与供应商、参数分层；长节点名支持悬浮和键盘查看；“来源 · 详情”可查看模型、供应商、参数、实际尺寸、时间并复制任务编号。
- 状态显示等待开始、正在提交、正在生成、下载保存、已完成、需要处理；等待时间独立更新。错误先呈现原因及处理建议，上游原文和技术信息折叠并支持复制。
- 区分“取回已有结果”与“重新生成”。重新生成入口注明会发起新请求。
- 连续青蓝短尾光约 72px，停下约 180ms 淡出，按需绘制、不使用粒子。空白处生效，编辑、菜单、拖拽和绘图期间隐藏。
- 连线仍只有被选中节点相关边或选中边发光，使用连续矢量羽化；长线滤镜按曲线控制点范围及缩放限制。
- 动效偏好跨项目保存；系统减少动态同时停用尾光、流光、过渡与镜头动画。拖动和缩放时暂停高成本发光。
- 缓存节点展示数据和未变节点对象；端口只批量测量发生变化的节点；小于 50% 缩放时未激活提示词使用轻量预览，点击即可编辑；多选不生成每个节点的尺寸手柄。
- 一并交付图片下载代理修复。模型请求参数与现有生成 API 保持兼容。本轮无付费生成，无新增便签或节点备注。

## 性能记录

测试为 Windows 本机 Chrome、生产构建、1280×720 视窗；50 / 200 / 500 个提示词节点与串联连线，适应全图后分别进行单节点拖动、双向滚轮缩放、全选拖动。以 requestAnimationFrame 间隔记录 p50、p95、最大值及大于 50ms 的帧数。它是本机合成压力场景，不代表所有显卡、素材和工作流。

最终无 DOM 快照录制的 p95 帧时间（ms，越低越好）：

| 节点数 | 拖动 | 缩放 | 多选拖动 |
|---|---:|---:|---:|
| 50 | 16.7 | 11.1 | 11.2 |
| 200 | 11.2 | 33.4 | 33.3 |
| 500 | 22.3 | 99.9 | 72.1 |

200 节点单节点拖动 p95=11.2ms，大部分帧约 5.6ms；但缩放及全选拖动 p95 约 33ms，未达到全部操作持续 60fps 的目标。500 节点全图缩放 p95 约 100ms、大量多选约 72ms，仍有明显慢帧，应作为后续优化项；不能据此宣称超大画布完全流畅。

原始数据保存在 `.codex-temp/canvas-polish-20260921/performance-final.json`。

旧基线只测了拖动，没有旧版缩放、多选基线，不能声称这两个操作的严格前后百分比。最终默认关闭 Playwright DOM 快照录制，避免快照开销污染性能结果；保留同样录制条件的一轮用于与旧基线比较。

相同 DOM 快照录制条件下的拖动 p95 前后对比（ms）：

| 节点数 | 修改前 | 最终版本 |
|---|---:|---:|
| 50 | 11.1 | 16.6 |
| 200 | 33.4 | 22.2 |
| 500 | 88.9 | 27.8 |

50 节点没有测得改进；200、500 节点有改善。不同轮次存在系统调度与垃圾回收波动，不把单次数据当成保证。两轮原始 JSON 均保留。
