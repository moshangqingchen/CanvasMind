## 持久化供应商核验

能力证据按供应商、配置来源、连接、分组、模型和操作绑定。连接密钥与配置使用带密钥的指纹；接口不会暴露该指纹、凭据或供应商签名结果 URL。旧数据通过可选字段兼容迁移。

- 明确限制优先，1K 分组不探测 2K/4K，未知质量只补一次 1K；4K 分组补齐 2K/4K；固定尺寸型号不会虚构其他尺寸。未知 1K 显示默认假设。
- 未明确的图片生成型号仅测试缺失的 2K/4K，使用适配器最高合法质量、一个比例、每次一张。有质量枚举拒绝时，每个型号/配置最多补一次返回枚举中的最高合法值，防止错误枚举引起连续付费重试。没有执行协议或仅编辑的型号保留跳过原因。
- 解码最终文件验证像素；两个方向至少达到目标 90%，比例误差不超过 2%，才接纳近似档位。参数接受不会被描述成已经验证视觉质量差异。
- 价格保留供应商原币种/积分及计费单位；组合不明确显示未知，不换算人民币、不重复乘分组倍率。仅能精确关联请求/任务的账单参与扣费比较，无法关联记作未核对；差异暂停后续核验。
- 按用户最新要求，覆盖每个有可用连接的分组里的不同图片型号，取消原“每家 6 次”的总上限。每个型号只测试缺失的 2K/4K，各一张；分辨率已知但质量未知时只补一张（含 1K 分组）。同一分组的重复连接去重，其他分组保留独立证据。
- policyVersion 2 将待测用例逐项持久化，计划提交总数 = 历史已占用次数 + 尚未提交用例数。旧版 6 次账本保留所有编号和占用，只补缺失项目；不退回失败或不确定提交的占用。全局串行，提交前原子保存编号、状态和占用；刷新和重启不重发结果不明的请求。
- 保存有效连接并免费读取成功后建立计划；普通 GET/打开页面不会产生新的付费提交。提供暂停、恢复、核对、取消未提交和显式单项重测；按分组查看不同型号、测试状态、来源与跳过原因。未配置分组 Key 或没有执行协议的项目不冒用其他连接。旧版账本的“新一轮”接口仅用于兼容，完整覆盖计划不再需要追加 6 次。
- 测试图片独立归档，不加入用户图片库。旧配置迟到的结果保留记录，不覆盖当前配置的有效能力。
- 已纳入智元 API 历史结果不明请求 `0ddc7ea3-f7cc-4d13-bfc2-8767dda1193f`，暂停等待核对，不重发。

## 性能实测

Chrome / Windows、本机 1280×720，关闭逐操作追踪，50/200/500 节点含对应连线。下表为每帧间隔 p95，单位 ms；同一测试、优化前后抽样，不是所有硬件的帧率保证。

| 节点数 | 拖动（前 → 后） | 缩放（前 → 后） | 多选拖动（前 → 后） |
|---|---|---|---|
| 50 | 11.2 → 5.7 | 11.1 → 11.2 | 11.2 → 5.6 |
| 200 | 11.2 → 11.2 | 39.0 → 22.2 | 33.3 → 5.7 |
| 500 | 22.3 → 33.3 | 100.0 → 72.3 | 66.7 → 11.2 |

来源：`performance-redesign.json` 与 `performance-viewport.json`。优化取消节点外层重复模糊投影，在视口层保留合成缓存，并关闭交互期间的阴影过渡。200 节点中位帧间隔约 5.6ms，但缩放 p95 仍超过 16.7ms；500 节点单独拖动有回退，不能宣称全程稳定 60fps。

1000 张隔离图库滚动：99 个采样帧，中位 5.7ms、p95 10.4ms、最大 79.8ms，同时挂载 15 张卡片。真实桌面 24 张原有图片：中位 5.6ms、p95 7ms、最大 22.3ms。尾光回归使用 React 提交计数确认鼠标移动不增加节点渲染次数。
