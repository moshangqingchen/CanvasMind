# Synora 供应商接入与验证说明

本报告公开接口合同、型号匹配规则和验证边界，不包含账户流水、凭据关联编号或本机安装记录。

## 接口与型号匹配

[Synora 官方接入文档](https://synoralink.com/docs)使用 OpenAI Images 兼容接口：

- 型号目录：`GET /v1/models`，Bearer API Key；权限必须来自该连接自己的目录响应。
- 文生图：`POST /v1/images/generations`，JSON 请求。
- 图片编辑：`POST /v1/images/edits`。
- 图片返回可以为 URL 或 Base64，取决于具体模型与上游。

接入按完整型号和对应分组处理，不能把其他分组的权限、价格或能力套到当前选择：

| 分组 | 对应完整型号 | 能力处理 |
| --- | --- | --- |
| 高质量生图专线 | `gpt-image-2` | Image 2 使用 high 默认规则，分组声明与实测分别标记 |
| 高质量生图专线 | `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` | Image 2.5 保留 max 最高候选，未执行的组合不写成已实测 |
| gpt-image-2（adobe） | `gpt-image-2` | 独立匹配 Adobe 分组，不补入其他分组型号 |

公开通用文档没有明确以上每个分组的专属质量枚举、4K 像素表或同步请求恢复接口，因此保留现有 Images 同步接入。公开型号广场不可用不能证明已认证连接没有型号或报价。

## 余额错误与鉴权错误

HTTP 403 本身不能确定 API Key 无效。明确的 `INSUFFICIENT_BALANCE` 应归类为余额或可用额度不足，保留已有型号目录；真正的凭据或型号权限拒绝仍按鉴权流程处理。

模拟契约测试应同时检查 HTTP 状态、服务端原错误码与错误展示，避免只按通用状态覆盖供应商实际原因。

## 已证实的结果与验证方法

独立单张验证曾使用 Adobe 分组的 `gpt-image-2`，请求 `size=3840x2160`、`quality=high`、`n=1`。返回的原始 PNG 可解码，实际像素为 3840×2160，比例为 16:9；没有通过缩放或后期处理补足尺寸。

此结果只证明对应分组、型号和请求组合的输出像素，以及该次请求接受 high 参数。不能据此保证其他分组、其他质量，也不能仅凭输出像素判断上游生成过程是否原生。不同质量之间没有进行主观画质对照。

方法包括保存原响应、下载原始图片、解码读取像素、比较请求尺寸与比例，并将真实验证与模拟 HTTP 或参数菜单检查分别记录。

## 参数与未测试边界

菜单遵循统一规则：Image 2 默认 high；Image 2.5 默认 max，并保留 auto 与适用候选。已开放的分辨率档位保留全部 11 种比例和 auto。候选、供应商声明和成功实测分别标记。

未取得结果或终态证据的请求不能记为参数不支持，也不能凭汇总缺记录认定没有收费。存在不确定提交时应暂停核对原请求，不自动重复购买或降低质量重发。

[批量接口说明](https://synoralink.com/batch-image)属于独立任务合同，不能把单张同步请求编号充当批量任务编号，也不能凭批量查询路径推断同步请求可恢复。

验证未覆盖全部分组、质量或尺寸。后续核验应保持分组和完整型号的精确范围，不将单个通过结果推广为全站保证。
