# Image 2 / 2.5 透明 4K 实测（2026-10-05）

本轮按用户授权，检查本机已配置供应商的最高质量 4K 图片线路，排除词元/TK1688。仅向图片接口的 JSON 请求体加入 `background: "transparent"`、`output_format: "png"`，测试提示词只描述陶瓷狐狸摆件，没有透明、Alpha 或背景要求。

## 覆盖与验收

- 共核对 92 个分组/型号组合，涉及 14 家供应商。
- 本轮实际提交 78 次，每个组合最多一次；另复用此前 Synora Sunburst 的成功结果，没有重复收费提交。
- 13 项未提交：7 项模型目录认证返回 403，4 项当前密钥目录没有该型号，2 项官方明确不支持 4K。
- 18 项通过：供应商原始 PNG 为 **3840×2160**，既有真正透明的像素，也有可见像素。
- 其余已提交结果：12 项取得不透明图片，14 项尺寸不符合，35 项接口拒绝、供应商失败或结果未确定。
- 原图没有本地抠图、合成、重编码或放大；检查包含文件签名、像素尺寸、Alpha 像素计数及 SHA256。
- 失败项没有自动重投或改路由再次生成。异步任务只继续查询原任务。

## 主要未通过情况

- 沧元两个可用分组的三个固定 4K 型号都返回了 4K PNG，但没有真实透明像素；备用分组的模型目录认证失败，没有付费提交。
- 智元本轮所测三个分组的 Image 2 / 2.5 均明确拒绝透明背景参数。
- 阿飞及辰途部分线路返回 JPEG 或 3584×2016；部分线路虽带 Alpha，仍不符合本次 3840×2160 验收。
- WeAI Codex、secure-skill 部分 Image 2 路线返回了真实透明图，但实际尺寸约 1K，不能归为透明 4K。
- pDog 超分组返回不透明图，与其原生组的透明能力不同。
- 怪兽部分线路返回尺寸不符的图片，两个最高 `-max` 型号本轮遇到上游 500/502；不能据此次失败推断其永久不支持透明。
- 辰途官 key 线路报告预扣费额度不足；具体是本站还是上游账户额度未确认。
- secure-skill 当前 2.5 文档明确仅支持 1K，且忽略背景参数，未提交无效的 4K 测试。喵呜新 2.5 型号的本机密钥目录查询返回 403，也未提交生成。

## 实现与适用范围

`packages/providers/src/transparent-image-evidence.ts` 保存精确身份、请求合同、日期和原图透明像素证据；UI 与请求校验共用能力判断。PDog 专属参数映射已补齐两个透明字段，保留原异步任务处理。另修复怪兽、智元官方根地址遗漏 `/v1` 的问题。

实测证明的是本轮最高质量、指定尺寸的**文字生图**，不是对所有尺寸、档位、参考图编辑或蒙版编辑的逐项验证。原有声明支持的透明/蒙版合同保留，临时网络或上游失败不被错误当作永久能力撤销。

模型选择框及展开的型号列表显示能力小标注：`可透明` 表示当前供应商、分组和型号支持透明 PNG 输出；`可编辑` 仅表示支持涂抹蒙版的局部修改，不包括普通参考图或一般图生图。能力标注与生成模式共用判定，随分组、型号和档位更新；已移除、鉴权失败或协议未适配的型号不显示能力标注。标注只用于当前界面，不写入项目文件。

Alpha 生效不等于边缘一定干净。部分结果保留大范围半透明阴影或灰晕，主体也有轻微透明度；完整透明像素占比已经逐项记录，未将这些原图描述为保证可直接用于精细抠图的素材。

完整原图、逐次结果及账单关联记录保留在本地忽略目录 `.codex-temp/transparent-all-20261005/`。账单读取/关联不足的项标为待确认，未把接口失败或暂时没有账单等同于未扣费；各站点额度不跨供应商、跨单位合并。仓库文档不保存账号、密钥、余额、请求 ID 或签名下载链接。
