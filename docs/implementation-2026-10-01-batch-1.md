## 已实现的行为

1. **错误与任务证据**：`No available compatible accounts` 显示供应商当前没有适用模型或线路的可用账号，旧的 `generation_failed` 记录也能重新解释。提交阶段的 502/503/504 提示先核对原任务与扣费；查询阶段的同类错误提示继续查询原任务。画布节点、来源详情、任务中心和诊断导出增加保存的连接名称、模型分组及原供应商任务号。接口名称标为“接口协议”，本地运行编号与供应商任务号分开显示。只公开白名单任务证据，不公开恢复快照、密钥或原图响应；本地同步接口占位编号与云端回执不当成供应商任务号。
2. **运行快捷键**：高优先级 Tiptap 绑定阻止 `Ctrl+Enter` 和 `Ctrl+Shift+Enter` 插入换行，事件仍交给现有 React 运行逻辑。普通 Enter、Shift+Enter 保留换行，中文组合输入不触发运行。
3. **操作反馈**：保存、退出等待遮罩及退出/更新错误提示采用共享的中性深色面板，显式文字颜色、加载指示、长文本换行及内部滚动。减少动效时加载指示保持静态；返回软件的原有回调保留。
4. **键盘焦点**：统一为 2px 实色焦点环，并覆盖旧样式的 `outline: none/0`。画布缩放控件和低缩放提示词使用内侧焦点，避免被裁切。

错误说明没有改变自动重试和恢复规则。未知提交不会自动重发付费请求；展示已接单或已失败不等于确认扣费或退款。供应商的服务可用性需要由其恢复，本次客户端改动不能消除上游 502 或账号池短缺。

## 本机退出故障补充

本次切换检查版时，安装版在没有生成任务的情况下显示“仍有任务正在运行”。现场生命周期为 `activeRuns=0`、`activeVerifications=0`、`activeWrites=1`。进一步核对，智能体、生成服务、供应商核验和实际保存队列都已空闲，也没有未完成的 HTTP 响应。最终完整快照的 `flush()` 成功，保存代次为 241，等待队列为 0。备份与正式资料库 SHA-256 一致，保存在 `%LOCALAPPDATA%\SuperCanvasDesktop\backups\exit-check-20261001-1006\super-canvas.json`。在这些条件再次核对后，仅纠正该旧进程的残留计数；旧版随后按原有保存、停止通道、关闭后台流程退出。调试监听已关闭。

代码核对发现，原监控只在响应 `end/finish` 时释放写计数；真实 Next 响应管道在连接断开后可能直接返回或销毁响应，没有调用 `end`，因此请求处理完成后仍可能留下计数。没有记录原请求路径，所以不能断言现场残留来自哪个接口。

检查版追加以下修复：

- 退出弹窗分别显示生成、供应商核验、保存与后台写入的数量；只有后台写入时，标题改为“正在完成保存与后台写入”。
- 观察 Next 实际异步请求处理函数的完成；只有它已经结束且响应已销毁时，才释放断开连接留下的 HTTP 计数。同步回调及未知监听器继续保持等待保护。
- 智能体与导演的 SSE 后台处理单独计数，覆盖完整执行、错误处理和清理，直到实际工作完成才释放，避免连接先断开就提前退出。

验证：桌面测试 38 项通过；后台写入辅助函数与导演接口 18 项通过；其中使用项目真实 Next 响应管道重现 JSON 与流式请求断开后不调用 `end` 的情况，并验证实际延迟写入完成前计数仍保持。定向 ESLint、TypeScript 和生产构建通过。重新打包后的 `verify-release --unpacked` 和 Electron 冒烟检查 23 项通过，包含保存、正常退出与重启恢复。测试使用隔离资料库及本地模拟请求，没有真实付费生成调用。

现场切换完成：运行进程及后台执行文件均已核对来自 `apps/desktop/release/win-unpacked`，首页正常加载原资料库。原有 169 条任务记录仍在（115 条成功、39 条失败、15 条待核对）；13 组供应商核验仍全部暂停。没有替换系统安装版或发布新版本。
