# Windows 桌面 App

超级画布当前专注 Windows 10/11 x64 桌面 App。安装包内置 Electron、Node.js 24、画布界面和本地 API，无需另装开发工具。`apps/desktop/renderer` 是桌面内嵌界面与本地 API 的源码目录，仍参与 App 构建；独立网页版、公网登录及服务器部署代码已移除。App 保留内嵌界面和仅供 Electron 访问的本地 API。

## 安装与资料

运行 `SuperCanvas-Setup-版本-x64.exe`，通过桌面或开始菜单打开“超级画布”。首次启动可以创建空白资料库，也可以选择旧仓库根目录或旧版安装目录迁移。

迁移前完成或取消旧版任务，并退出旧版服务与守护程序。迁移复制数据库、素材、项目归档和 API 密钥，不修改原目录。发现运行任务、缺失素材、无法解密的历史连接或迁移期间数据变化时，不启用不完整的资料库。失败的 `migration-*` 目录保留作诊断，重试使用新的临时目录。

桌面资料存放在 `%LOCALAPPDATA%\SuperCanvasDesktop\profile`，日志在相邻的 `logs` 目录。安装、升级、卸载不会清除资料。`secrets.bin` 使用 Windows DPAPI 保护主密钥，不能只复制这个文件到其他 Windows 用户来恢复凭据；跨机器迁移项目可使用完整 `.supercanvas` 项目包，在新电脑重新配置 API Key。旧目录中的原密钥和数据应一起保留作原始备份。

关闭窗口后软件留在托盘，生成继续执行。托盘菜单“退出”先保存画布；还有任务时可选择等待完成或返回软件。电脑睡眠、关机或断网期间无法保证供应商任务完成，重新打开后会按原运行记录恢复；提交结果不确定时要求人工处理，不自动重复付费。

App 通过 API 联网生成，不附带本地 AI 模型。支持直接上传的接口使用本地素材字节。0.2.29 起，需要公网参考素材的接口可在创作设置的「素材通道」页连接自有域名：填写 HTTPS 域名及现有 Cloudflare 隧道凭据，将隧道路由限制到 `/api/provider-assets/`，服务地址设为 `http://127.0.0.1:3210`。需要安装官方 cloudflared 客户端；无需开通 R2 或上传素材到公共图床。

本机通道只提供带有效签名的素材读取，链接 1 小时后失效；不公开画布、供应商、凭据或其他管理接口。原素材仍保存在本机，读取期间需要电脑联网且 App 运行。Cloudflare 与所选供应商会处理素材，持有有效链接的人也能读取素材。隧道凭据由 Windows DPAPI 加密保存，随 App 启停连接。每次提交前检查公网连通；已启用本机通道时，断线不会回退到公共图床。

没有自有通道时，也可在「供应商与模型」对应分组开启「参考图临时链接」并保存。此选项默认关闭，启用后只在运行相应模型时将参考图片匿名上传到 Litterbox，并申请 24 小时过期链接。此公共图床仅支持图片；自有通道则按本地素材类型提供读取。保存两类通道设置均不会发起模型核验或收费生成。

## 资料备份

从托盘选择“退出”，确认 App 和生成任务都已停止，再复制整个 `%LOCALAPPDATA%\SuperCanvasDesktop\profile` 目录到备份位置。数据库、素材、项目和 `secrets.bin` 必须保留为同一份备份集；日志可按诊断需要单独保存。不要在 App 正在写入资料时只复制数据库。

同一 Windows 用户环境中恢复时，先退出 App 并保留当前资料目录副本，再将完整备份放回 `profile`。Windows DPAPI 凭据与用户环境绑定；跨电脑或跨 Windows 用户迁移请导出完整 `.supercanvas` 项目包并重新配置 API Key。项目包不包含运行历史或未引用素材，不能替代完整资料备份。

## 更新

0.2.22 起，在“供应商与模型”设置中点击“刷新全部供应商”，会逐个扫描已保存供应商（包含隐藏的供应商，不扫描未配置的内置模板）。刷新目录分组、名称及各 Key 的模型清单，显示进度和各供应商结果。新增分组需配置对应 Key；更换分组 ID 时不会自动转移原 Key。旧分组未再返回时移到独立区域，密钥和历史保留。

模型的“可用”表示最近一次 Key 模型列表已返回且应用支持调用协议，并不代表做过付费生成测试。新模型标记“新增”，移除模型保留“未再返回”记录；网络失败标记待确认，鉴权失败单独提示，不据此删除数据。关闭设置再打开可以继续查看本次刷新进度。

启动及每六小时检查正式 GitHub Release；也可以从托盘或画布设置中手动检查。用户选择下载，下载完成后再选择“重启并更新”。保存失败或任务尚未完成时不会安装。下载失败可以重试，当前版本仍可使用。

桌面版使用独立更新器。发布新版本时同步增加根 `package.json` 与 `apps/desktop/package.json` 的版本号，并编写 `docs/releases/v版本号.md`；推送到 `main` 后自动构建、验证并发布。也支持推送对应 `v*` 标签或手动运行发布工作流。已经发布的版本会跳过，修改同一版本源码不会重复覆盖正式安装包。

流程先构建并校验安装包、blockmap、`latest.yml` 的版本、哈希及更新说明，再运行回归与打包版冒烟测试。所有资产先上传到草稿 Release，完整后才公开，避免客户端提前读到缺失文件。更新说明同时写入安装包和更新清单。新版在首页和画布内均自动弹窗，每个版本在当前会话提醒一次；下载和重启安装分别由用户选择。

旧安装缺少 `resources/app-update.yml` 时，需要用完整安装包覆盖安装一次；新版还会为缺失配置建立本机兜底，保障后续检查和下载。开发版不启用在线安装。

客户端不包含 GitHub Token。首版不要求商业签名；如配置 Windows 签名，应在 CI 中通过 electron-builder 的签名凭据接入，不能将证书或密码提交到源码。

## 开发与验证

在 Windows x64 的 Node.js 24、pnpm 11 环境执行：

```powershell
pnpm install
pnpm dev
```

`pnpm dev` 首先构建共享包与 Electron 主进程，随后由 Electron 管理本机 Next 开发服务和共享包编译监听器；内嵌 UI、本地 API 和共享包修改自动更新，修改桌面外壳后需重新启动。开发模式使用独立的 `%LOCALAPPDATA%\SuperCanvasDesktopDevelopment\profile`，首次自动创建空白库；关闭窗口会安全退出并停止子进程。开发 HTTP 和 HMR WebSocket 都要求桌面会话令牌。

`pnpm desktop:dev:production` 保留完整生产构建与 stage 启动流程，使用标准桌面资料库。已准备运行资源且源码未变时，使用 `pnpm start` 或 `pnpm desktop:start` 直接启动。开发桌面壳不安装在线更新。打包运行依赖由 `apps/desktop/runtime-package-lock.json` 固定；升级依赖并构建界面后，显式执行 `pnpm desktop:lock` 并审核锁文件，再打包。

验证与打包：

```powershell
pnpm typecheck
pnpm test
pnpm lint
pnpm desktop:test
pnpm build
```

`pnpm build` 与 `pnpm desktop:build` 均构建 Windows x64 安装包，输出到 `apps/desktop/release`。`pnpm desktop:build --unpacked` 只构建未安装版。`pnpm build:runtime` 只构建内嵌 UI、API 与共享包，供跨平台质量校验，不产出 Electron 安装包；桌面启动与打包需要 Windows。

生产构建使用独立 `.next-desktop` 输出，补齐静态资源和导演知识库。stage 校验不含环境文件、画布数据库、凭据文件或符号链接，并验证内置 Node.js 的官方 SHA-256。后端仅监听回环地址，每次启动使用独立访问令牌；渲染层不直接取得 Node.js 权限或主密钥。

发布验收应覆盖无 Node.js 的普通 Windows 用户环境、中文路径、旧资料迁移、Fake Provider 运行、退出保存、托盘运行及两个正式版本之间的安装更新。没有新版本 Release 时，线上更新只能验证“无更新”和网络失败分支。
