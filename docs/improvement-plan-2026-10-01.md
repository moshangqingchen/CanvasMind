### 2.2 今天的故障说明了什么

北京时间 2026-10-01 07:17–07:21 的最近 5 次尝试：辰途 3 次 502、We-AI 1 次 502、secure-skill 接单后返回 `No available compatible accounts`。4 次 502 在约 1.5–2.5 秒内由服务器返回；这些尝试没有重叠执行。昨天辰途 Sunburst / max 改图有成功记录，但尺寸不同，不能视为完全同参数对照。

现有证据主要指向供应商服务/账号资源问题。降低并发、延长超时、换提示词不能被写成已经验证的根因修复。应用能改善的是错误解释、批次保护、任务追踪和可恢复性；供应商自身容量仍由供应商解决。

`OpenAI Images API` 在当前错误展示中来自协议适配器标签，不证明请求直连 OpenAI 官方。`No available compatible accounts` 当前落入泛化的 `generation_failed`，这是应首先修正的解释缺口。

## 3. 实施时必须保持的行为

1. 同一用户操作重放最多产生一个运行；用户有意创建的新一轮生成仍然有效。
2. 同一节点任务的提交结果未知后，自动付费提交次数不得增加。查询、恢复和取回使用原任务或已保存响应。
3. 有任务 ID 的查询失败不等同于远端生成失败；本机停止跟踪不等同于供应商取消成功。
4. 恢复、取消、删除和重启不得丢掉尚未核实的付费任务证据。
5. API 成功响应与持久化提交一致；写盘失败不能被下一次保存静默变成先前操作的成功。
6. 账号累计消耗、余额变化与本次任务扣费分开。只有足够的供应商账单关联证据才能判断该任务费用。
7. 生图保留用户选择及当前可用最新 image2.0 / image generation 模型的要求；不会通过自动换商、降质量或本地文字、二维码、排版、图片合成替代生成来处理失败。供应商别名本身不作为模型真实性证明。

上述提交次数按节点任务与用户操作分别计数。恢复整个 DAG 时，明确尚未提交且仍保有原授权的后继节点可以按定义继续派发；它们不能被混算成对已提交节点的重新购买。取消、暂停、授权失效的运行不能因此恢复新提交。

这些是故障夹具与发布验收的断言，不是依赖开发人员记忆的提示语。

## 5. 关键方案与验收

### 5.1 生成故障：原因、提交事实、费用事实分开

在现有 `status`、`errorJson`、任务快照和时间线上补充兼容字段，不立即另造一套运行状态机。先定义共享错误契约，使服务端 `error-presentation` 与前端 `error-localization` 使用一致语义；旧记录缺字段时保守解释。

| 任务证据 | 展示与动作 | 付费边界 |
| --- | --- | --- |
| 本地校验拒绝，尚未发送 | 显示具体模型/尺寸/素材限制，允许修改后生成 | 此次请求尚未提交 |
| 提交阶段 502/断线，无供应商任务号 | “提交结果未知”，显示真实渠道与核对入口 | 不自动重发；费用未确认 |
| 已有任务号，远端失败且报缺号 | “供应商暂无可用兼容账号”，保留任务号 | 远端生成失败不证明未扣费；新生成是另一次操作 |
| 已有任务号，查询网络失败 | “查询暂时中断”，恢复原任务查询 | 只读查询，不新建生成 |
| 已收到成功响应，下载/归档失败 | “图片已生成，保存结果失败”，取回已保存结果 | 优先重新归档，不重新生成 |
| 已停止本机跟踪 / 远端取消未确认 | 分别显示停止跟踪、取消请求已发出、远端确认或已完成 | 不宣称停算或退款 |

第一批增加 `No available compatible accounts` 专项分类，也识别供应商的 overloaded/system under load 等已知原文。保持原文供技术详情查看，但不把 HTML 放在主要提示区。主要信息顺序为：原因 → 真实供应商/分组/型号 → 当前任务事实 → 可执行动作。协议名放在技术详情。

任务中心已有诊断导出，应扩展白名单字段：本地 run/node ID、真实供应商/连接名称、模型、操作、阶段、HTTP 状态、可用供应商 task/request ID、结果与账务核对状态。域名不带 URL 用户信息和查询令牌；错误摘录限长并脱敏。提示词、参考图、完整响应、Key、Cookie、签名下载地址、任意供应商响应头不进入普通诊断包。

验收用今天的 502/缺号响应制作离线夹具：画布与任务中心结论一致；已有任务号可复制；历史旧记录仍可读；未知提交没有无条件“自动重试”按钮；诊断包通过秘密字段与敏感文本检查。

### 5.2 后续选项：线路健康与批量暂停

本节是储备设计，本次第一批不实现。若用户批量生成时确实反复遇到故障，先增加“暂停当前批次剩余节点”；以下完整统计和跨重启保护再按需求扩展。

把目录扫描结果、生成近期表现、余额读取结果分开。模型 GET 正常、余额正常、历史出图成功，都不等于当前账号池可接单。

第一版用最近业务请求的被动证据展示“未观察 / 最近成功 / 近期异常 / 暂停新提交”，带时间、错误样本与样本数量。小样本不显示有统计意义的稳定成功率，也不做供应商排行榜。

暂停范围首先按连接来源、配置版本、型号和操作类型区分；只有供应商明确表明更大范围故障时才扩大。建议初始策略为短窗口连续两次同类网关/容量错误后，暂停同范围尚未派发的付费任务；阈值可由夹具校准，单次异常先提示。

已接单任务继续查询、取回和归档。暂停只改变未提交队列，明确显示已提交、等待确认、未提交三个数量。用户继续当前批次时重新检查当前配置与原报价；不能自动换供应商、换型号、降参数或为未知任务补买一张。更换 Key/地址/分组后旧健康证据不串到新来源。

不新增后台付费探活。暂停解除可依据有效供应商服务证据或用户已授权的新业务请求；免费模型列表不能单独解除“生成已恢复”的判断。

验收：连续失败暂停未派发节点；健康的其他连接继续工作；原 taskId 的 GET 与归档不受暂停影响；进程重启不会重新提交未知任务；暂停计数与实际 provider submit 次数吻合。

### 5.3 订阅、快捷键和草稿应用

`connections → applyRunSnapshot → subscribeToRun → effect cleanup` 的依赖链确实会重建订阅并清理部分活动记录。SSE 是观察渠道，不能拥有付费操作身份或决定任务是否已经提交。

抽出 `useRunSubscriptions` 时同时明确三类生命周期：用户操作/请求 ID、服务端活动任务快照、SSE/轮询连接。关闭或重建 SSE 只释放流和定时器，不释放提交事实；404、CLOSED 与临时重连由对账处理。最新连接信息可用受控引用读取，但不能只加 ref 就跳过配置变化的正常响应。

快捷键按“输入法组合 → 弹窗/局部编辑 → 智能体修改事务 → 画布快捷键”处理。Ctrl+Enter 的现有换行问题确实可以小修：在已有高优先级编辑器扩展加入 `"Mod-Enter": () => true`，外层 React 仍能收到冒泡并运行；可另加 `"Shift-Mod-Enter": () => true` 明确保留下游运行用途。代码改动很小，与相应回归一起交付，无需单独估计一个开发阶段。回归验证提示词逐字一致、运行范围正确、中文组词期间不提交、普通 Enter/Shift+Enter 仍正常换行。执行时先刷新编辑器草稿，再针对将要提交的同一份图做校验与保存。

智能体应用与确认回执分开：图已应用、回执写失败时准确提示，重试只补回执。以 proposal/draft ID 标记已应用，避免再次插入节点或启动生成；键盘也要遵守修改互斥，不能只依赖 DOM `inert`。

验收：Ctrl+Enter/Shift+Ctrl+Enter 提交的提示词与输入逐字一致；IME 组合期间不运行；设置反复开关、断网和重挂载，同一操作只提交一次；刻意独立新生成仍有效；草稿确认失败后节点数与提交数不增加。

### 5.4 仓储原子迁移与数据库恢复

已有原子 rename、Windows 重试、写队列与 flush，应保留并明确其作用：它们降低半文件与并发替换风险，不等于已验证断电持久性和业务事务。

先定义一次保存包含哪些改动：在独立副本中准备并检查运行、节点和项目变更，确认这些记录的版本仍一致后一起保存，再安排外部执行。JSON 仓储可采用排队保存，或先在副本上修改、保存成功后统一替换；索引、历史缓存和磁盘快照同步更新。保存失败时维持之前已保存的状态，保护其他并发操作。

新资料和恢复副本先写入各自的临时文件，确认已写入磁盘，再完整替换，并核对保存版本号。替换期间始终保留至少一份可读的已保存资料。恢复副本检查格式、版本和完整性；损坏原件单独保留，好副本继续可用。遇到更高版本的资料时给出兼容性提示，避免误当作损坏而退回旧资料。

恢复流程沿用原 taskId/已保存响应；取消意图与节点迁移一次提交，启动/周期对账/退出 drain 都读取待取消集合。对旧版不一致记录做保守修复。供应商不支持取消时保留“停止跟踪”的真实语义。

创建运行和删除项目共用仓储项目门禁。删除时检查活跃、待取消、未知提交和待取回证据；涉及未核实任务时先处理或归档，明确放弃后也保留最小任务证据。文件夹删除另做幂等补偿，不能把数据库与文件删除宣称为一个事务。

启动时分别恢复普通任务、云端任务和待取消任务，控制同时处理的数量；单个失败后继续其他任务。视频/音频保存查询截止时间，等待与网络查询均可中止，重启后沿用原截止时间。到时显示“需要处理”并保留任务号，说明本机暂停了查询。

验收覆盖 EIO/ENOSPC/EPERM、并发修改、write/sync/rename 失败点、main 坏/backup 好/两者坏、首次写入、取消与恢复竞争、删除与创建竞争、各阶段强杀重启。已有提交证据或提交结果未知的节点，恢复时付费 submit 增量必须为 0；原运行中明确未提交的后继节点按剩余授权单独验收与计数。强杀证明进程中断恢复能力；真正断电持久性需另做 Windows 环境验证，不能混称。

先完成 JSON 仓储的可靠提交协议。SQLite 作为后续评估项：只有目标规模的写入/恢复基准或事务复杂度表明现方案不可持续时，才设计迁移、双读核对、回退和安装包兼容；不与 UI 改造一并迁库。

### 5.5 大素材、导入安全与 GC

范围读取与普通下载都采用流、背压和客户端中止，获取一致的对象句柄/元数据后允许并发读，保留发布与删除的一致性。8 MB 可作为内部预算候选。若主动只返回请求范围的一部分，需要准确 `Content-Range` 并验证播放器续请求；优先实现完整请求范围的流式响应。HTTP 本身允许部分范围先返回，不能把所有子范围响应判为违规。[RFC 9110 §14.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)

上传按路径分步改造：直接上传的视频/音频边读边写临时文件；表单上传还要处理解析表单时的内存占用，单改 `File.stream()` 不够。图片转换/修复限制同时处理数量并使用磁盘中间文件，保留现有微信图片、HEIF、JPEG 完整性及元数据处理。核对实际文件大小、解码像素和并发内存；失败清理本操作临时文件，数据库保存完成后再报告成功。

远程导入复用下载底层能力，但使用显式的用户素材信任策略：逐跳地址检查、直连固定解析地址、TLS 主机名校验、HTTPS 不降级、请求中止和大小检查。代理模式的 DNS/路由属于代理信任边界，不能继承供应商结果下载的全部例外策略后声称已解决重绑定。

GC 本次保持只读预览。需要实际回收空间时，先确保应用、后台服务、迁移和清理工具不会同时修改同一资料目录；清理全过程独占，删除前再次核对资料版本与文件信息。端口检查只作辅助。正在上传、归档的临时文件，以及恢复记录和备份仍引用的素材均受保护。先输出候选文件清单，需要完整清理功能时再加入隔离与保留期，最后删除。

后续素材修复验收：500 MB 视频开放 Range、seek、多路慢读、断开、并发读写/删；半上传、伪大小、两大视频、超限及图片修复夹具；DNS 重绑定/私网重定向/HTTPS 降级的模拟测试。内存与延迟目标在同机基线后确定，不凭空规定一个通用 RSS 数字。

GC 专项验收属于储备，仅在实现实际清理时执行：上传写文件与保存数据库的间隙、App 中途启动、旧备份引用、junction 与失效锁。本次只读预览不承诺已具备这些删除保护。

### 5.6 桌面退出、崩溃、端口和隧道

退出分为准备、等待任务/保存、确认退出、关闭程序。保存失败且仍可回退时返回工作界面；窗口销毁或后端终止后，辅助状态文件写入失败也继续完成退出。先确认任务与草稿已保存，再终止由本程序启动的子进程。回退后第二次退出可执行，并核对仍可使用的窗口与服务。

在已有 backend exit 错误页/重试基础上补 renderer/utility 崩溃处理与脱敏诊断。有限次恢复后显示故障页；重载只恢复观察和草稿，不新建付费请求。主进程致命错误不能一律吞掉继续运行。

端口信息完整写好后再替换；识别端口占用错误后有限次重试，每次先确认本程序启动的旧子进程已退出。原端口决定浏览器本地存储来源，先处理草稿/偏好的可见性，避免随机换端口后像是“资料丢失”。迁移仍在无法确认旧服务停止时拒绝继续，只补编码、路径规范化和错误说明。

隧道先修完整清理与明确的重连入口，再加入有限退避。error/exit 双回调、停止与重试竞争、进行中的参考图下载需有一致状态；不能一律关闭网关导致供应商读图中断，也不能恢复隧道时重发生成任务。

### 5.7 界面：先统一使用规则，再统一细节

视觉基调：紫色用于品牌与主要操作；画布和属性面板使用克制的中性深色；成功、警告、失败、信息有各自语义。玻璃效果限于少量浮层，不增加大面积画布滤镜。

迁移路线：

1. 建语义令牌与旧变量兼容层，先保持当前有效样式；用 computed style 和截图确认，不把后加载补丁盲目替换成新色值。
2. 第一组只做 Button、IconButton、Modal、Panel 与输入框规范，先落到任务中心和设置的高频操作。
3. 原生 Select/Checkbox 先补可读性、键盘与完整选项说明。只有原生能力不足的复杂模型选择才扩展现有 picker，不一次自建全套控件。
4. 逐屏迁移设置 → 任务中心/错误卡 → 画布工具栏/参数面板 → 项目菜单 → 比稿/平面设计 → 智能体。功能修复与视觉搬移分开评审。
5. CSS 清理跟随已迁移组件。动态类名、第三方类名、状态类和特殊模式用运行截图验证；确认孤儿文件后单独移除。

Modal 复用现有焦点能力，并明确顶层 Esc、焦点陷阱、关闭后焦点归还与未保存内容策略。嵌套菜单/弹窗的 Esc 只处理最上层。相关键盘行为依据 [W3C Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

字号以正文 12–14px、标题 13–16px、少量标签 11px 为起点；重要状态不能只靠小字号或颜色。普通文本目标对比度至少 4.5:1，大字至少 3:1，按实际生效前景/背景和半透明合成色验证；静态色卡估算不作为通过证据。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

测试 980×680、1280×720、1440×900 与更大窗口，并覆盖 Windows 缩放、页面缩放及侧栏展开后的实际 CSS 视口。四图比稿按可用内容宽度切换 2×2/单列，布局不能只依赖原生窗口宽度。

画布端口字号与点击区域还要在常用画布缩放下验证。新建节点使用视口/选中节点的确定落点与避让，用户已移动节点不自动重排。属性面板中的供应商、型号、尺寸、质量与报价保持可见，减少“去设置找状态、回画布重新选”的往返。

颜色/样式规范以新增组件 lint 和迁移清单推进，不以“颜色只剩 30 个”“全局 CSS 只剩几行”作为完成标准。更少的覆盖层、可预测的组件行为、真实内容下的可读性才是验收目标。

### 5.8 撤销、导入、输入同步与性能

导入使用独立 import ID 和生命周期。建议默认“撤销正在导入的插入 = 取消该插入”；晚到结果不复活节点，已经归档的素材可保留在素材库并准确提示。redo 是否重新插入已有素材由同一记录决定，不能直接合并全部临时节点到所有历史快照。桥接超时只改变责任归属，浏览器 fallback 与 native completion 必须有一个最终发布者。

历史按实际图变更入栈，在修改前取得旧快照，在确认操作有效时提交历史；不能把 checkpoint 搬到 store 修改之后。自动状态补丁、保存状态、选择变化和生成观察不污染用户撤销记录。

提示词编辑器使用版本/dirty 策略处理外部更新：没有本地未提交修改才同步；冲突保留用户草稿并可见提示，不能在 blur 时无条件 `setContent` 覆盖输入。画布全局快捷键与局部编辑快捷键边界明确。

缩放/绘制采用合并检查点，但退出、手势结束、运行与离开画布仍 flush。调整 IndexedDB 防抖时先定义最大可接受草稿丢失窗口；不能只为了性能去掉恢复能力。selector 优化配合 memo 与稳定节点身份，不能指望 `useShallow` 消除节点数组变化带来的所有重渲染。

持续沿用 50/200/500 节点、混合图片、千图图库以及 1k/10k/50k 运行记录夹具。比较同机相同构建模式、视口和采样配置的 P95、长帧与峰值内存。重构先抽稳定边界与纯函数，按 `useRunSubscriptions`、`useAssetImport`、`useCanvasHistory`、`useCanvasShortcuts`、智能体应用边界拆；避免只按行数搬出另一个大文件。

## 7. 验证、发布与回退

### 7.1 验证分层

执行前先检查当前终端：`Get-Command pnpm, corepack`、`pnpm --version`。本轮 Codex 终端已能运行 pnpm，返回 **11.19.0**；项目 `package.json` 声明 **pnpm@11.9.0**，验证前应对齐项目声明版本。普通外部 PowerShell 的 PATH 可能不同；缺命令时可检查已有 Corepack 或使用明确的工具路径，不把“机器一定没有 pnpm、必须先重装”作为事实。若使用 Corepack，先用 `corepack pnpm --version` 检查其选中的项目版本，再确定执行入口。

| 层级 | 运行内容 | 时机 |
| --- | --- | --- |
| 变更级 | 相关包单测、状态/故障夹具、相关 UI 交互 | 每个行为切片，先验证真实风险，不为文案或搬移写镜像测试。 |
| 合并级 | `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm test:maintenance` | 按仓库统一入口；不把某个 renderer 子集冒充全仓测试。 |
| 场景级 | Playwright 的生成、设置、恢复取消、保存冲突、导入、布局等受影响 spec | 功能改动后；共享 UI、任务或数据层改动扩大回归。 |
| 版本级 | 完整相关回归、生产构建、打包程序 smoke、真实 Windows 更新/启动/退出核对 | 每个候选发布版本，记录源码版本、BUILD_ID、程序包与实际启动路径。 |
| 性能级 | 现有画布/图库/仓储夹具，同机前后对照 | 新的性能改动或测量显示回归时；不为每次文字修改重复跑全量。 |

测试使用隔离临时资料库、Fake/本地模拟供应商及关闭自动付费核验的配置，不指向个人资料库。端口由测试配置确定，不在方案中写死“3211”。安装版验收不等于源码测试；真实供应商可用性也不等于 Fake 测试通过。

### 7.2 发布门槛

- 付费夹具：同一节点操作最多一次 submit；该节点未知提交后自动 submit 增量为 0；已有 taskId 的节点恢复不新建生成。多节点运行中尚未提交的后继节点继续执行时另计，并验证原授权仍有效。
- 状态夹具：恢复/取消/删除的所有交错要么完整提交、要么完整拒绝；原错误与任务证据可查。
- 数据夹具：故障点恢复到可校验的提交，不同损坏/版本情况有准确提示。备份引用素材的 GC 删除保护为储备功能验收，仅在实现实际清理后适用。
- 素材夹具：大文件与断开场景不整段复制增长，seek 与图片修复行为保持正确，失败不报告成功。
- 界面场景：错误动作一致，中文不截断关键任务/模型信息，窗口/缩放/侧栏组合可操作，键盘焦点可见。
- 性能：同机目标场景没有超出约定噪声的回退；门槛在基线后记录，不能通过放宽阈值或仅采样模式声称通过。

采用可独立评审的行为切片，一份改动围绕一个用户结果；数据库协议与依赖业务修复按依赖关系组织，不强求原清单“一条一个提交”。数据变更先确认恢复路径，程序回退与数据版本兼容一起设计；不能只恢复旧程序而忽略已写入新格式。

### 7.3 第一个可交付批次

首先完成：今天两类错误的离线夹具与共享分类、真实渠道/任务号展示、统一未知提交动作，以及 Ctrl+Enter 提交文本回归。并行复现“设置开关导致活动任务丢失”与“取消后立即退出”，为第二、三批确定边界。

这一批的用户收益很具体：能知道是哪条渠道出错、任务是否已接单、接下来是查原任务还是核对账单；运行快捷键不会改坏准备提交的内容。后续再让这些事实跨设置开关、断线、重启和资料恢复保持一致。
