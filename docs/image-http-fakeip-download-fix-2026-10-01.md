# HTTP 图片链接在 Fake-IP DNS 下取回失败

2026-10-01，辰途 `image2.5全参` 的一次 `gpt-image-2.5-sunburst` 同步生成已返回成功响应，但本地任务进入 `needs_attention`，错误为：

```text
供应商任务已完成，但输出归档失败：Provider output URL resolves to a private address
```

## 已确认原因

响应中的 `b64_json` 是空字符串，`url` 指向 `http://img2.duolapi.cn/images/...png`。空 Base64 的校验已生效，程序正确使用了 URL；这次失败发生在下载前的 DNS 地址校验。

本机系统 DNS 返回 `198.18.1.214`。旧下载器仅允许 HTTPS 域名使用 Fake-IP 映射，因该链接使用 HTTP，按保留地址拒绝访问。独立公共 DNS 返回真实公网地址 `135.148.171.58`，固定该地址并保留原域名 Host 后，原图成功下载。

界面此前把所有 `artifact_archive_failed` 都显示为“下载到素材库时中断，可以直接取回现有结果”，掩盖了安全检查主动阻止下载的原因。

通过当前应用的归档流程保存到素材库并关联原任务，再复用已保存的成功任务及完整归档结束该运行。恢复后运行和节点均为 `succeeded`，原供应商任务 ID 保持不变，提交尝试次数仍为 1。

## 修复

`packages/runtime/src/remote-download.ts` 仅对 HTTP 域名、且系统 DNS 全部为 Fake-IP 的情况进行独立公共解析。取得真实公网地址后固定目的 IP；显式代理路径也固定相同目的 IP，并保留原 Host。真实内网、Fake-IP 或私网字面量、包含非公网地址的混合解析及每次重定向仍接受原有安全校验；公共解析失败不回退到 Fake-IP。

`apps/desktop/renderer/lib/error-localization.ts` 对地址拦截显示明确原因，技术详情保留已知标准诊断。其他归档失败提示改为可尝试取回，避免承诺点击即可解决。

## 发布前完整检查补充

真实 Undici 代理检查发现，`fetch` 会把手设 `Host` 改写成目标 IP。专用 HTTP 取回路径改为低层 `request`，使请求目标仍为已验证公网 IP，同时保留原域名；使用真实本地代理测试请求、重定向、流式取消、大小限制和总超时。

在总超时或根据 Content-Length 提前拒绝过大文件时，Node 流转换存在取消后仍向已关闭控制器写入的风险。专用桥接现在先记录关闭状态，再取消底层响应，并在每次异步读取返回后检查关闭状态，避免未捕获的控制器异常。成功响应使用 identity 编码，阻止把压缩传输字节误存为图片；重定向仍交由下载器逐跳验证。

首轮 221 项浏览器回归中，219 项通过，两项图片预览测试发现同一节点在缩略图尺寸从 160 升级到 640 后又下载一次原图。原因是预览组件把尺寸链接也作为内部身份，导致原图回退状态被重置。现改为按素材身份保留回退状态及 Blob 引用，更换素材仍重置；保留原测试的一次下载断言。
