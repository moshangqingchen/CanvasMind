# 参数框覆盖生成节点修复

日期：2026-10-09（America/Los_Angeles）。范围为节点参数面板布局，不涉及供应商能力或收费生成。

## 原因

用户截图中的“模型与参数”面板覆盖了视频生成节点。旧定位先尝试在节点下方和上方放置完整面板（560 个画布单位高），均不足时把面板夹到画布可见范围内。这条回退只检查视口和工具栏边界，没有排除节点矩形，所以高缩放、靠下节点或较矮窗口中会直接压住提示词与节点操作区。当前安装版 0.2.82 也包含这条回退。

旧 `attached-panel-geometry.ts` 测试辅助函数重复了生产定位公式，并接受 `clamped` 结果，因此“面板在视口内”通过时仍可能遮挡节点。

## 修改

- 按节点外侧的实际剩余空间定位；优先下方、上方完整展开，再检查侧方。
- 空间不足时限制面板高度并使用原有内部滚动，保留节点位置、尺寸和画布缩放，不再通过把面板推回节点区域解决越界。
- 创作栏、底部工具栏、缩放控件和小地图继续作为避让区域。
- 监听小地图等工具的动态挂载和移除，面板打开后再切换工具也会重新定位。
- 候选区域同时检查可操作高度；优先使用可读的窄侧栏，避免十几像素高的区域把标题、关闭按钮和全部控件裁掉。
- 模型下拉列表的顶层浮窗也遵守画布和创作栏边界，修复窗口缩窄后覆盖左侧工具的情况。
- 浏览器回归直接检查面板和节点、工具栏是否相交，以及真实控件点击和滚动，不再复制定位算法。

节点完全占满视口，或四周只剩不足以容纳标题与控件的细条时，面板保持完整尺寸并位于节点外，需平移或缩小画布后查看；不会通过覆盖节点或把面板裁成细条来强行放入视口。

## 0.2.85 合并前复核

合并审查补出一个边界：节点几乎占满视口、下方仅剩 10px 时，原候选回退仍会选中这条不可操作区域。新增回归先检出 `maxHeight=10`，修正后只选有足够标题与控件高度的区域；均不满足时采用上述节点外完整面板回退。测试还验证向上平移后恢复到视口内、保持至少 120 CSSpx 可操作高度且不覆盖节点。

此补充属于源码复核；最终合并版生产构建、浏览器回归和安装版验收需以新版本的验收记录为准，不沿用此前 Build 的结果冒充。

0.2.85 最终回归又覆盖到 980px 窗口、200% 缩放的真实组合：节点下方和底部工具栏之间剩余 208 屏幕像素，即 104 CSSpx。只允许 120 CSSpx 高度会错误跳过这块可操作空间，把面板推到视口外。修复后仍优先选择至少 120 CSSpx 高的常规或窄侧栏；没有这类区域时，常规宽度面板可使用至少 96 CSSpx 的区域，保留约 49 CSSpx 的固定标题栏和内部滚动区。窄侧栏仍要求至少 120 CSSpx，10px 细条不接受。新增单测使用该实际节点、工具栏和视口矩形，保持节点与工具避让；布局单测共 12 项通过。最终生产回归仍要求几何误差不超过 1px、关闭和管理按钮完整可见、实际字段可滚动操作。
