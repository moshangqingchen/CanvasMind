# GPT Image 2.5 供应商能力核验

核验日期：2026-09-10。只核验当前已保存 Key 实时返回的 GPT Image 2.5 模型；不把 Gemini 2.5 或截图里的官方能力套用到转发渠道。

晚间更新：辰途「低价Adobe生图」Flare / Sunburst 已重新实测成功生成真实 4K，且六档质量在 1K 均可调用。以下辰途早期拒绝记录保留作历史证据，当前配置以 [辰途晚间复测](chentu-image25-recheck-2026-09-10.md) 为准；「1k低价生图」不继承 Adobe 组能力。

实际提交 72 次请求（原始 68 次，另补测辰途 4 次；含无效参数对照和 9 次图片编辑）。所有请求均已结束；其中 FriModel Sunburst 的 xhigh 在 240 秒后超时，没有把它标为成功或新增选项。

先阅读各供应商文档、模型广场和能力接口，再对未写明的能力提交实际请求。生成提示词统一为红色陶瓷杯与左侧蓝球，编辑要求仅将杯子改成绿色。下载输出后读取文件真实像素，而不是相信响应里的 `size`。质量测试包含无效值对照，防止把参数回显误判为有效支持。

FriModel 最终质量选项：Flare 为 auto/low/medium/high/xhigh/max；Sunburst 为 auto/low/medium/high/max。Sunburst 的 auto 成功且返回 medium；xhigh 虽在供应商错误响应枚举中出现，但这次实测超时，暂不新增。该超时不等于供应商永久不支持。

We-AI、喵呜的现有 Key 返回 403，无法确认其最新 2.5 库存；智元和其他成功扫描的分组未返回 GPT Image 2.5，均未新增能力。

## 实现与验证

- 比例修正：每个已开放档位提供 1:1、16:9、9:16、4:3、3:4、3:2、2:3、5:4、4:5、21:9、9:21 共 11 个预设及自动比例。根据档位像素预算、最长边和 16 像素对齐计算宽高；这些预设并非逐个付费实测，原来的三个实测尺寸只用于确认档位能力。
- 切换档位保留所选比例；自动比例在提交前优先解析提示词，其次参考图，无比例时使用方图。独立分辨率 SKU 的自动比例保留该 SKU 档位。
- 辰途「低价Adobe生图」早期补测：Flare、Sunburst 分别以省略质量及 `quality=low` 请求 `3840x2160`，四次均返回 HTTP 400 `image_size_policy_error`。这是当时观察到的渠道限制；晚间已由实际 4K 图片推翻，详见单独复测报告。同组其他型号的能力仍不自动继承。

- 新增的能力绑定按供应商域名、分组和精确模型 ID 隔离；鉴权拒绝仍保持拒绝，其他模型不继承。
- 缓存模型在读取时重新绑定能力，REST connector 同步更新，避免界面显示新档位而提交仍使用旧描述。
- FriModel 服务端放行经核验的两个 Adobe 2.5 模型的编辑与高级质量；旧 2.0 和未知 2.5 名称仍使用原验证规则。
- 已有部署管理器自动构建并更新本地 3210 服务；通过实际模型 API 刷新 9 个现有分组，检查返回的参数与编辑能力。
- 本地原始响应摘要及样图保存在 `.codex-temp/probe/image25/`，其中 `results.jsonl` 不包含 API Key；可提交的脱敏摘要见 `image25-provider-probes.json`。
- 初次能力更新验证：providers 40 项测试、web 50 项测试全部通过；providers 构建与 web TypeScript 检查通过。抽查各渠道编辑样图，均能将杯子变为绿色并保留左侧蓝球。比例联动另增加像素约束、局部档位、提示词/参考图优先级及提交参数回归测试。
