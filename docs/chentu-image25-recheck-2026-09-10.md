# 辰途 GPT Image 2.5 晚间复测

2026-09-10 晚，使用当前已保存的分组 Key 重新读取 `/v1/models`、`/v1/image/model-capabilities` 和 [API 文档](https://tu.988236.xyz/docs/api-media.zh-CN.md)，然后提交实际生图请求并读取下载图片的真实像素。

本次结果更新了当天较早“低价 Adobe 组 2.5 只允许 1K”的结论：低价 Adobe 分组的 Flare 和 Sunburst 都已实际生成 3840×2160。能力接口仍列旧的 1K 尺寸，不能代替此次实际输出验证。

实测时间为北京时间 21:17–21:35，共 81 次请求：57 次得到图片、2 次无效质量对照返回 400、21 次暂时无可用账号返回 503、1 次网络失败。所有请求及补测均已结束。

两个 Adobe 型号的 `high` 竖版 2160×3840、方图 2880×2880 均返回精确尺寸；请求 4096×2304（low）均返回 3840×2160，因此本次证实的横向 4K 是 3840 宽，而非 4096 宽。

低价 Adobe 两个型号请求 2048×2048（分别省略质量、high）四次均返回 1920×1920，未将其标为精确 2K。画布增加这两个精确型号的 1K/4K 控件及六档质量；每档提供 11 个比例和自动比例，预设按像素预算计算，本次实际覆盖方形、横版和竖版，未逐个测试所有比例。其他分组不继承这些能力。

Sunburst 的 `xhigh + 3840×2160` 在暂时缺号后曾返回 1344×768；针对同一参数连续两次重测均为 3840×2160。由此确认该组合可以达到真实 4K，同时保留此次尺寸不符记录，不承诺每次上游输出均达到请求尺寸。原始逐次记录包含该次小图，汇总表的 `actualSize` 表示最后一次得到图片的结果。

测试过程出现 `503 No available compatible accounts`，恢复后相同请求能够成功。它属于本次观察到的渠道资源问题，不能直接归类为质量/尺寸不支持。逐组合结果、重试次数与真实尺寸记录在 [脱敏实测记录](chentu-image25-recheck-2026-09-10.json)。六档接受性不等于已定量验证各档视觉提升，也不表示每个质量与尺寸组合均无资源波动。
