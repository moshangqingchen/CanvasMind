# 供应商模型验证完整规则：生图与智能体

更新：2026-09-24。本文合并用户对接口、价格、分组、分辨率、全部比例与自动、全部质量、最高质量测试、失败重试、智能体大模型思考档位及证据记录的要求，作为完整执行及验收规则。尺寸与质量选项按本次规则统一展开，替代旧文档中“必须先实测最高档成功才展开”的限制。本文是规范；具体自动接入范围见末尾实现说明。

**执行主体是画布应用本身：接入供应商并保存有效分组 Key 后自动开始读取和验证，不需要再点“测试”，也不需要再次要求 Codex 开始。** 手动新增/更换 Key、变更接入来源/分组/协议，以及账号登录导入 Key，均自动进入流程。仅添加供应商地址但尚无 Key 时，可以读取公开目录，不能假定具有模型调用权限。

- 先保存连接与待处理标记，再在后台主动刷新当前 Key 的模型、分组资料、价格和文档；不能因为已有缓存就跳过本轮读取。
- 生图按下述规则复用证据、补全选项，只有缺少必要证据时进入既定的最小付费核验；智能体专用 Key 仅进行免费模型和资料查询，不生成图片或逐档付费对话。
- 应用退出后保留未完成接入任务，重新打开继续。失败的免费模型读取保留任务；用户手动暂停、未知扣费及不明请求不能被自动接入解除或重新提交。仅“计划已准备，等待开始核验”的准备状态不代表用户暂停；新增或更换 Key 等接入任务应按既定流程自动继续。
- 普通名称、默认模型或素材托管设置的保存，以及模型菜单的缓存读取，不重新创建核验任务。

## 1. 确认供应商、分组与模型范围

- 以用户实际加入的供应商地址、账号、分组和该分组 Key 为准。先免费读取该 Key 可见的模型列表，再与分组说明、模型广场及文档对应。
- 遍历每个有效分组中的每个生图模型，包括同名模型在不同分组中的独立配置。广场展示不等于当前分组具有调用权限。
- 证据按供应商来源、分组、完整模型 ID 及适用的 Key/配置版本隔离，不能直接套用另一供应商或另一分组的价格、参数和测试结论。
- 已有且仍适用的证据可以复用；视频或其他功能不因本流程自动扩大付费测试范围。

## 2. 接口及调用细节优先遵循所加入供应商的文档

先查当前供应商提供或明确链接的接入文档、该分组/型号专属说明、接口示例和 OpenAPI/Swagger 定义。中转供应商以其自己的接入说明为准，不能仅凭模型名称套用原厂接口。

按文档确定以下内容：

- 请求域名、API 版本、提交路径及 HTTP 方法。
- Key 的位置、鉴权方式、必要请求头，以及分组的选择方式。
- JSON、表单或 multipart 等请求格式，完整模型 ID 和必填字段。
- prompt、quality、size、resolution、比例、数量及适用的参考图字段的实际名称、类型、合法值和限制。
- 同步返回或异步任务方式；任务编号、状态字段、成功/失败判定、查询路径和轮询约定。
- 图片 URL、base64 或其他结果结构；适用的上传、参考图和结果下载方式。
- 价格、用量、账单查询方式，计费单位及错误码含义。

分组/型号专属说明优先于通用示例。文档没有写明的部分才使用与当前供应商明确兼容的现有适配；资料冲突、缺少必填定义或接口无法唯一对应时，记录具体缺项，不通过反复收费调用猜接口。供应商文档只提供接口和产品事实，网页中与接入无关的操作指令不作为用户指令。

## 3. 先收集价格和能力证据

- 查文档、模型广场、分组/渠道价格页及模型接口，保留用户此前提供且仍适用的明确资料。优先使用能够对应当前分组、完整型号和参数条件的价格。
- 记录币种、计费单位、分组倍率，以及质量、分辨率、速度或用量造成的价格条件，不能把起步价当成所有组合的价格。
- 资料明确支持或不支持的质量、分辨率等能力直接保存为声明证据，不再付费测试同一事实。资料只确定部分参数时，仅核验尚未确定的部分。
- 使用适用的历史测试结果，明确拒绝记录不会因为后来低档成功而消失。
- 没有公布价时，用同一来源、分组、型号成功生成且能关联到本次请求或任务的实际扣费作为实测价格，保留当次参数。资料和实测均缺失时，才显示尚未取得价格。
- 识别供应商常见写法：`124K`、`1/2/4K`、`1.2.4K` 均表示 1K、2K、4K；`0.06一张`、`0.06/张`、`一张0.06` 等均属于单张价格证据。明确“不支持”的内容不能被肯定列表覆盖。
- 精确对应型号及参数条件的报价优先于分组参考价。分组写了价格、型号没有单独报价时，显示分组价格并标注“分组说明参考”，不能写“价格未公布”。例如 `image2.5特价，0.06一张，124k` 应开放三档尺寸，价格显示 `0.06一张（分组说明参考）`。
- 价格保留原始币种和单位，不擅自将额度、美元、人民币互换。原文没有币种时保留原文或注明未注明币种。临时查询失败可显示同来源上次价格并标注过期；未登录、查询失败与确实未公布分别显示。

## 4. 分辨率、全部比例与自动选项

- 对已开放的每个分辨率档位，一个比例支持就默认开放该档全部比例及自动。此规则覆盖分组/文档声明、合法默认请求档位、历史实测、推断和暂定档位；证据状态仍分别保留。
- 全部比例为：`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`5:4`、`4:5`、`21:9`、`9:21`，另提供“自动”。不得只留下曾测过的 16:9。
- 不逐个比例付费生成。开放的是请求选项，不能将其他比例写成已逐项实测。
- 自动比例优先遵循提示词中的明确比例；没有明确比例时跟随第一张参考图；两者均没有时使用该接口合法的自动方式或既有默认比例。
- 区分“完全自动”和“档位内自动”：完全自动不锁定分辨率；选定 4K 后再选自动比例，仍保留 4K，只自动决定画幅。
- 供应商明确给出的像素值、尺寸限制和必要对齐规则继续有效。已有尺寸保留，只补足缺失比例；实际发送供应商要求的字段与像素值，内部档位标记不冒充上游参数。
- 原生接口将分辨率与比例分成两个参数时，同样补齐比例和自动，不能只修复 W×H 类型接口。
- 同一完整型号在当前分组 4K 通过后，可推断开放 2K，标为“由 4K 推断”，取消尚未提交的重复 2K 核验；不伪造 2K 测试记录。
- 一个比例的支持不等于另一个分辨率已经实测通过。独立的 1K/2K/4K 型号、明确拒绝的档位和不同分组不能相互替代。

## 5. 全部质量选项与最高默认值

- 同型号最高合法质量被说明支持、实测接受，或作为适配器默认合法请求值时，默认开放该型号全部合法质量选项，并将最高合法档作为默认值；不再要求每档质量单独付费测试。
- GPT Image 2.5：`auto`、`low`、`medium`、`high`、`xhigh`、`max`，默认 `max`。GPT Image 2：`low`、`medium`、`high`，默认 `high`。
- 其他模型依其文档及参数定义处理。没有 `max` 的模型不强行添加 `max`，质量固定在独立型号或分组中的接口保留其固定映射。
- 供应商已明确拒绝的质量值、返回的合法值限制继续生效。请求超时、繁忙、限流或缺号不等于质量参数不支持。
- 最高档明确不支持时，不用该值推断全部质量；按其余合法值及有效证据处理。低档成功不能反过来证明高档成功，也不能把未确定的高档标成不支持。
- 新节点默认选最高，已保存节点保留用户选定的质量。不能因为刷新模型、更新缓存或重开画布而把用户选择重置。
- 菜单展开与证据记录独立：默认开放的档位仍可标为待核验，已接受的质量请求也不表示主观画质差异已经得到验证。

## 6. 制定每组、每模型的测试计划

- 对缺少证据的模型，先选一个比例、一个尺寸和一个最高质量组合，每次请求一张图。普通生图测试不使用用户私有素材。
- 最高档以该供应商对此型号的说明和合法参数为准：明确最高只有 2K，就从 2K 开始；4K 是待核验的候选最高分辨率时，才从 4K 开始。不能把所有模型强制写成 4K/max。
- 未明确限制的新图片型号沿用 4K 优先自动核验，并在菜单展示 4K 待核验；不能把缺少说明显示成只支持 1K。明确只支持 1K、固定档位型号及合法原生枚举仍按其限制处理。
- 提交阶段一个分组的 Key 鉴权失败仅阻止该连接的测试，不连带阻止其他新分组；旧请求保留且不自动重发。手动暂停、结果不明或扣费异常的暂停继续保留。
- 质量顺序依据该型号的参数定义。只有确实适用时才采用 max → xhigh → high 等顺序，不发明未定义的档位。
- 不遍历全部尺寸和比例；通常保持选定尺寸，只在需要且有明确尺寸拒绝证据时调整尺寸。
- 保存计划、证据、请求参数和待测状态后提交，成功一次即结束该模型本轮自动测试。

## 7. 按文档提交并核对实际图片

使用已经确定的供应商接口、鉴权和请求格式。每次提交保存唯一请求编号；异步接口取得任务编号后按文档查询原任务。查询超时或暂时断线时先恢复原任务状态，不另发一次生图请求。

取得返回结果后检查是否真的有图片，记录原始像素、比例和返回信息。HTTP 成功或任务状态成功本身不足以证明请求档位已实现。

实际图片按以下顺序判定：

1. 能下载、能解码，并取得有效的实际宽高；缺少图片或无法解码不算通过。
2. 比例必须符合请求。当前允许相对比例误差不超过 2%；近似分辨率不能放宽比例要求。
3. 宽、高均达到该次请求像素，记为该请求档位通过。各比例按自己的合法像素预设比较，不把所有 4K 比例强制写成同一个长边。
4. 未达到请求像素，但比例合格时，按用户的近似规则处理：2K 长边至少 1536 像素、4K 长边至少 3072 像素可记为对应近似档位；当前 1K 容差为宽高均达到请求值的 90%。近似档位必须保留“近似”标识和原始像素。
5. 达不到上述条件或比例不符，记录实际结果及待核验状态，不自动解释为该档位被接口明确拒绝，也不自动再买一张补测。

## 8. 根据失败原因与扣费证据分流

| 结果 | 记录与后续动作 |
| --- | --- |
| 成功且图片与请求相符 | 保存实测成功、图片信息和实际费用，结束该模型本轮测试，进入下一个模型。 |
| 明确拒绝 quality 等质量参数 | 只将被拒绝的值/组合记为不支持；依据返回的合法值或文档选下一质量。下一次提交仍须满足未扣费条件。 |
| 明确拒绝 size/resolution 等尺寸参数 | 区分字段格式错误与档位不支持。修正文档规定的格式，或在明确档位拒绝且未扣费后选择下一合法尺寸；不据此认定模型整体不支持生图。 |
| 繁忙、限流等失败，且确认本次未扣费 | 不标记档位不支持；同一尺寸按质量从高到低继续，成功即结束。 |
| 最低合法质量仍失败，且确认未扣费 | 保存延迟重试状态，从 5 秒逐步增加等待至最多 5 分钟；可以继续处理其他可执行模型。已有暂停和执行限制继续有效。 |
| 没有账号、账号池为空或没有可用上游 | 保留未被明确否定的最高候选档位，标记“暂定，待核验”，记录缺号原因并进入其他模型；不伪造实测成功。 |
| 已扣费但失败 | 保存账单和失败结果，暂停自动重发，避免继续购买失败请求。 |
| 扣费情况不明或请求结果不明 | 保留请求/任务编号，先查状态及账单，暂停自动重发；后续确认失败且未扣费才能继续。 |
| Key 无效、权限不足、余额不足 | 记录接入问题，等待对应配置或账户问题解决；不通过降质量猜测修复，也不记成质量不支持。 |
| 成功响应无图片，或像素/比例不符合请求 | 记录不确定结果或真实输出尺寸并核对费用；不能仅凭这次结果判定档位不支持。有扣费或费用不明时不自动再买一张。 |

“未扣费”需要本次终态错误中的明确免扣费信息，或与请求编号/任务编号精确关联的零费用记录。未查到账单、账单尚未入库、查询失败和只看余额没变化，都不能直接当作未扣费。通用 400/500 错误也不能直接当作参数不支持。

例如某型号的质量顺序为 max → xhigh → high：4K/max 繁忙且明确未扣费，继续同尺寸的 xhigh；xhigh 返回明确不支持且未扣费，记录该值不支持并继续 high；high 成功后结束。本次 max 仍是待核验，不能因为 high 成功就把 max 标成不支持。

## 9. 回写价格、参数与证据

- 分别记录“文档声明”“实测成功”“由已知能力推断”“暂定，待核验”和“明确不支持”，同时保存来源、时间、适用分组/型号与参数。
- 记录请求质量、请求分辨率、实际像素、比例、请求/任务编号、费用、币种、单位，以及失败原因和重试关系。界面不展示 Key 或其他凭据。
- 公布价格用于对应的条件报价，实测费用另行保留；两者不一致时保留双方证据。没有公布价格才以实测费用补充展示。
- 实测价格标明“生成实测”及对应参数。改到未测价的组合时提示“当前组合未测价”，不能将一次生成费用当作所有档位的固定报价。
- 如由 4K 成功推断开放 2K，明确标注推断，不生成虚构的 2K 实测记录；独立 SKU 和已有明确拒绝证据不能被推断覆盖。
- 状态分别展示为“说明支持”“实测支持”“由已知能力推断”“近似档位”“暂定，待核验”“明确不支持”“需要核对”。声明、默认开放、推断都不改写为实测；互相冲突的资料保留来源并待核对，不静默选取有利结论。

## 10. 持久化、恢复与结束条件

- 每次尝试独立保存，重试生成新请求编号并关联原记录，不覆盖之前的失败或费用。
- 软件重启后继续已知任务查询和待执行队列；保持用户暂停状态，不自动重发结果不明的请求。
- 刷新价格、查看模型列表和修改显示名称等操作不等于重新安排付费测试。新的明确文档可以取消尚未提交的重复测试。
- 每个分组/型号最终应有可解释的状态：资料已确定、实测成功、明确不支持、缺号暂定、等待重试或待处理。仍有重试/待处理项时，不能声称全量测试成功。
- 新供应商、Key、路由或型号按既有自动接入设置进入扫描与计划；手动暂停或因结果、扣费问题暂停的队列继续暂停。准备计划造成的暂停仅由已保存的自动接入任务解除；打开页面、普通刷新或更新软件本身不解除暂停。
- 所有已有和新增供应商均走同一套规则；不能只给本次截图中的供应商或型号临时添加选项。

## 11. 界面、缓存与程序交付验收

- 实时目录和旧缓存都应用相同的解析、价格及选项展开规则。缓存读取不得联网重测或创建付费任务。
- 对 1K、2K、4K 每一已开放档位，检查全部 11 种比例及自动确实在下拉菜单中；同时检查完全自动和档位内自动的不同保存行为。
- 检查质量下拉菜单包含全部合法档位，默认最高；逐项选择、保存、关闭再打开、刷新和重启后，用户选定参数仍保留。
- 新建节点、切换供应商/分组/Key/型号时的质量值必须使用当前型号最高合法档位；旧缓存先返回 high、后续目录补齐 max 时，自动默认必须随目录更新。记录“自动默认”和“手动选择”的来源，不能把自动填入的较低值误作手动选择，也不能覆盖明确的手动质量选择。
- 实际请求采用当前选定的比例、档位和质量。界面可选、保存内容、参数校验与上游字段映射保持一致。
- 检查当前组合价格随分辨率和质量条件变化，分组参考价、过期价格和实测价有正确标注，已有价格不会被旧的“价格未公布”缓存覆盖。
- 使用模拟请求及隔离资料库验证界面和程序逻辑；修复参数、价格或界面不需要重新购买验证图片。
- 根据变更运行相关回归、类型检查、静态检查、界面保存恢复测试和打包后检查。不能只证明模型接口返回了“4K”，却不检查该档的比例和自动选项。
- 更新实际使用的桌面程序前正常保存退出并备份；更新后从已安装程序回读型号、价格和完整参数选项。保留画布、素材、历史测试、扣费记录及暂停状态，不回写旧数据覆盖用户后续修改。

## 12. 智能体大模型的思考强度规则

核心顺序：**先查当前供应商文档、模型广场及模型接口声明；缺少思考档位时，查清渠道型号与官方型号的对应关系，再用对应官方型号的完整合法档位补齐。**

- 供应商对当前分组、完整型号的明确档位、关闭限制或参数限制优先。不能因为官方型号支持某档，就覆盖该渠道已明确声明的不支持；当前 Key 的明确拒绝需要单独记录并影响该 Key 的可选值。
- 渠道没有声明档位，不等于不支持思考，也不能作为停止查证的理由。继续查看型号专属文档、模型广场详情、接口返回的原始型号/别名字段及已有可靠映射。
- 对 `gpt-pro-[稳定优先]` 等自定义名称，先查清其实际官方型号。不能仅凭名称相似、删除后缀、出现 `pro` 或“稳定优先”就猜型号；如果渠道会动态路由到多个型号，则按其明确公布的共同档位或路由约定处理。
- 一旦确认官方型号，查询该型号、版本及实际 API 协议的官方档位，完整补齐对应选项，保存官网来源、查询时间、渠道别名与官方型号之间的映射依据。实际请求仍使用供应商要求的渠道模型 ID，不擅自改成原厂 ID。
- 不要求每个思考档位逐项付费验证。只测过 high 不能让官方或渠道已公布的 low、medium、xhigh 等其他合法档位消失；最高档成功也不能凭空发明官方和渠道均未定义的档位。
- “渠道声明”“官网补充”“当前 Key 实测”分别标明。官网档位用于缺失信息的补充，不标成当前中转渠道已逐项实测。
- “自动”表示不强行指定思考强度，使用当前渠道/模型默认行为；它不表示关闭思考。`none`、`off` 等关闭值只有该型号及当前协议明确支持时才提供，不能与自动混为一谈。
- 下拉菜单、服务端合法值校验和真实请求字段保持一致。按实际协议发送，例如 OpenAI Responses、Chat Completions、Claude Messages、Gemini 各用自己的字段；只有思考预算的接口不将低/中/高擅自换算为预算。软件界面的 Ultra 等名称不自动等于 API 存在同名值。
- 保留用户已选思考强度。切换供应商、分组、Key、型号或协议后重新匹配合法值；旧证据不跨来源套用，被当前渠道明确拒绝的值不继续发送。
- 仅某个档位被明确拒绝时，只限制该档或该参数组合，保留其他合法档位。超时、网络错误、繁忙、额度不足、空响应或接口路径错误不能直接推断模型不支持思考。
- 完成上述查证后仍无法确认型号或档位，才保留自动，并写清“渠道未提供档位，尚未确认官方型号”等实际缺项；不能用长期“待识别”冒充仍在加载，也不能声称等待就会自动完成。
- 文档、映射或模型信息补齐后，更新已有缓存和当前模型菜单，不需要重新创建 Key，也不通过重复付费对话刷新菜单。

截图中的 `gpt-pro-[稳定优先]` 应执行“查当前渠道资料 → 确认官方型号/路由规则 → 读取该官方型号的档位 → 按渠道明确限制调整 → 更新菜单及来源”的完整路径。只解释名称不标准、只返回自动，未继续查证，不符合本规则。

## 13. 智能体输入能力、价格与验收

- 智能体只列入适合对话/推理的模型；生图、视频、向量、排序等模型不能仅因出现在同一个 Key 列表中就充当聊天模型。模型广场的展示不授予当前 Key 权限。
- 图片、音频、视频输入能力分别读取供应商声明。按已确认的默认规则，聊天大语言模型缺少图片能力声明时开放图片理解并标为“默认支持”；明确否定不能被默认值覆盖。音频、视频仍需明确声明及适配器支持。
- 上传数量、单个文件大小、单轮总量同时遵守供应商限制和应用限制，并分别展示。当前应用限制为每轮最多 16 个附件、单个 16 MB、总计 24 MB；不得静默丢掉本轮超限附件。历史附件因限额被省略时给出说明。
- 大模型价格按其实际输入/输出 Token、缓存或按次等计费单位及条件记录，不能套用生图的每张价格。官方基础价格也不能冒充中转渠道实际报价。
- 验收覆盖：渠道声明优先、官网回退、可靠别名映射、映射缺失的明确提示、自动与关闭思考的区别、单档拒绝、Key/分组隔离、协议参数映射，以及选项选择、保存、刷新和重开恢复。
- 使用模拟响应与已有有效证据检查上述逻辑；资料查询和菜单修复不等于授权额外付费对话。当前真实渠道未做过的调用不标成已实测。
