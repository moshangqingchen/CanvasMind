# 新增 Key 自动核验暂停修复

日期：2026-09-24。

## 原因

We-AI 的旧核验记录处于“计划已准备，等待开始核验”，`used = 0` 且没有提交记录。新增 Image2.5 分组 Key 后，自动接入已创建核验计划，但沿用了供应商级 `paused = true`。旧实现无法区分计划准备与用户手动暂停，导致只排队、不执行。这是程序遗漏，不是用户缺少授权。

## 修复

- 核验记录新增可选暂停原因：`preview`、`manual`、`safety`。
- 已保存的新 Key 等自动接入任务可以解除纯准备状态，按既定流程执行缺少证据的最小核验。
- 旧记录仅在准备提示精确匹配、从未提交请求且没有结果或扣费风险时兼容为准备状态。
- 手动暂停、取消、未知暂停原因、待核对请求及扣费异常继续阻止提交。普通计划刷新、缓存读取和重启本身不解除暂停。

## 验证

- 聚焦回归：2 个文件，69 项通过，覆盖旧/新准备状态、新 Key 接入、普通刷新、手动暂停、未知结果及扣费保护。
- 完整 renderer 回归：145 个文件，1,359 项通过。
- 4 个变更的 renderer 文件 ESLint 通过；生产编译及 TypeScript 检查通过。
- 打包桌面冒烟：23 项通过，使用隔离资料库，不提交真实付费测试。
- 已正常保存退出、备份并更新实际桌面程序，安装版本构建 ID：`s_CmWjZsVAwiGsKP1Okoz`。
- 从已安装运行时回读两个新模型：各档全部比例、自动、6 档质量和 4K 实测证据均保留。画布、素材及生成记录内容校验一致；We-AI 仍为已提交 5 次、7 项计划、暂停待核对。本次更新新增付费提交为 0。

新增的 `gpt-image-2.5-flare` 与 `gpt-image-2.5-sunburst` 已在此前补测中通过 4K/max，原始图片均为 3840×2160，详情见 [We-AI 新模型核验](weai-new-model-verification-2026-09-24.md)。本次程序修复不重复购买测试图片。该供应商后续 Gemini 核验的结果/扣费待核对暂停继续保留。
