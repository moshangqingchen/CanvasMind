# 第二轮复查 · 2026-10-05

在第一轮修改后的工作区再次检查，重点覆盖首轮测试未覆盖的组合操作、响应丢失、流取消和项目目录并发。保留第一轮检查记录，不用本轮测试覆盖其历史结果。

## 新发现与处理

1. **首页任务入口重复使用失败。** 三个设计快捷入口使用固定项目名，再次点击会收到重名错误。三个新增浏览器用例在修复前全部失败。现在创建前读取项目列表，为重复名称选择数字后缀，例如“做活动海报 3”，保留直接进入工作台的操作流程。
2. **素材写入与目录变更竞态。** 素材流仍在写入时，重命名、删除或清理项目可以先执行，随后归档失败。新增同项目读写协调：素材归档可并发，目录变更等待已开始的写入；不同项目独立处理。
3. **保存确认丢失被误报为版本冲突。** 服务端保存已完成、确认响应丢失后，客户端重试可能收到 409。相同标题与内容的重试需要先确认快照落盘，再重新核对当前数据；真实内容差异仍保留冲突。
4. **流式对话结束与取消边界。** 普通智能体收到结束事件后仍可能等连接关闭；取消发生在同一网络分片的事件处理之间时，剩余事件仍可回调。结束或取消后立即停止后续事件并释放连接。
5. **代理结果下载的清理阻塞。** 自定义响应流取消永不完成时，下载超时或磁盘错误可能被阻塞；超时后的迟到响应未释放。取消清理不再阻塞调用方，并回收迟到响应。
6. **IPv6 等价地址及非公网地址判断不一致。** 统一 IPv4-mapped IPv6 的点分与十六进制写法，修复公网等价地址误拒；补齐多播、站点本地等非公网地址拦截。
7. **项目列表损坏响应被显示为空库。** 对成功 HTTP 响应中的非法 JSON/错误结构显式报错，避免把损坏响应误当作项目为空或被删除。
8. **首次初始化可能提前确认。** 首次快照仍在写入或写入失败后，后续初始化不能仅因内存已有默认画布就返回成功。现在等待持久化；失败保留待写入状态，恢复后允许重试。
9. **额外 HTTP 监听器影响退出保护。** 存在日志等额外请求监听器时，已经发送响应的异步处理函数可能仍有写入工作。现在始终等待已跟踪的异步函数完成，再解除退出保护。

存储协调还经过独立交叉检查：同一素材的归档与删除、归档失败后的后续操作、双向重命名、大小写等价目录、初始化失败重试均完成，没有发现死锁或残留队列。协调范围是同一个 `ProjectFileStore` 实例；外部进程改目录，以及调用方在重命名后仍明确使用旧项目名，不由此屏障解决。

## 大画布检查

已执行真实浏览器中的 50、200、500 节点性能测试，分别使用纯提示词和混合图片场景，测量单节点拖动、缩放、多选拖动。独立性能检查与最终全量回归各执行一次；每次 6 个场景、18 组测量均通过仓库既有门槛。

独立检查中，500 节点的帧耗时 P95 约为 22.3–55.5 ms，单次最大峰值达到 200 ms。最终全量回归中，500 节点的 P95 约为 22.2–50 ms，最大峰值约为 188.8 ms。因此结果证明未超过已有回归门槛，并不代表所有大画布操作都能稳定达到 60fps。机器负载和浏览器状态会影响测量，原始数据见 [独立检查数据](canvas-performance-round2.json) 与 [最终全量回归数据](canvas-performance-round2-final.json)。
