# 生图失败与扣费功能复检 · 2026-10-05

本轮在已有修改上继续检查提交、任务恢复、扣费证据和界面状态。使用本地模拟供应商和隔离数据，不触发真实付费生成。

## 已复现并修复

| 问题 | 修复 |
| --- | --- |
| 创建任务后读取失败，或持久化查询异常，被当成未创建的参数错误返回 422 | 返回结果待确认的 503，让前端保留原提交编号；能读取原任务时仍返回原任务，不再次生成 |
| 已收到供应商响应后，本地进度保存报网络类错误，被误判为请求尚未发送 | 保留已经发送和收到响应的证据，不显示“本次未扣费”，也不据此自动重试非幂等提交 |
| `refunded: false` 或退款对象明确声明非退款状态，仍被退款金额覆盖成已退款 | 退款确认遵守显式状态；存在冲突时不宣称已退款 |
| 退款金额错误使用原扣费币种 | 优先保留明确的退款币种，不擅自换算 |
| 查询、下载请求自身的免费或退款信息覆盖原生成账务 | 这些 HTTP 错误响应的账务不并入生成任务，保留原任务账务证据 |
| 轮询或恢复返回其他任务 ID，结果或退款被写入原任务 | 核对任务 ID，不一致时保留原任务并提示人工核对 |
| 供应商主动取消后，整个工作流一直处于运行中；取消对账还可能丢失已知费用 | 正常结束工作流并阻止下游继续执行，取消及后续对账保留原任务的已扣费或已退款凭据 |
| 来源详情拿到最新成功状态和 `errorJson: null`，仍回退旧失败信息 | 最新节点记录中的空错误表示已清除，不再展示缓存中的旧失败和旧费用提示 |
| 取消记录被套用“失败原因”并暗示退款或再次生成 | 显示“取消信息 / 取消原因”，提示核对原任务及账单，保留已确认费用 |
| 上游账号余额不足被前端重新解释成用户余额不足 | 已确认的结构化分类优先；旧记录识别上游或账号池故障，不误导用户充值 |
| 明确用户余额不足时，结构化分类的提前返回遗漏原有官网入口 | 仅对明确的用户余额错误恢复已知供应商官网入口，供应商账号池错误不添加该入口 |

## 验证方式

新增回归先在修复前复现，再验证修改后的行为。接口测试同时核对客户端会将不确定提交保留为待核对状态；浏览器新增最新成功状态清错、取消信息和上游账户额度三个场景。

分模块单元与集成测试共 **3,118 项通过**：Core 30、DB 50、Storage 23、Providers 786、Director 24、Runtime 273、Renderer 1,891、桌面 41。维护脚本 12 项通过，工作区类型检查、ESLint 和共享包构建通过。Providers 在最后补齐收到响应后的代理配置错误分支后，再次完成 786 项测试、类型检查和构建；Renderer 在恢复余额入口后重新完成全包 1,891 项测试、TypeScript 及相关 ESLint。

本轮增加 29 项单元与集成回归：Providers 11、Runtime 7、Renderer 11。其中提交恢复 6 项用例的 4 项在修复前失败，来源详情的两个新浏览器用例也在旧构建上复现失败。

全量浏览器测试 **51 个文件、277 项一次运行全部通过**，用时约 12 分钟，没有失败重试。覆盖项目保存与冲突、模型参数、生成与取消、原任务恢复、素材导入导出、来源与历史、供应商和账务面板、首页及键盘操作，以及 50 / 200 / 500 节点的拖动、缩放、多选现有性能门槛。

最后的余额官网入口修复后，重新通过 Next 生产构建，并复验 14 个相关浏览器场景。13 项一次通过；余额入口用例补齐展开现有“技术详情”折叠区的操作后也通过。该复验确认结果卡片与历史的余额入口存在，供应商容量问题没有充值入口，最新成功状态清错与取消费用信息正常。14 项与全量场景重合，不累加为不同场景总数。

通过截图检查了 [取消任务仍保留已确认扣费](failure-recheck-cancelled.png) 与 [最新成功状态清除旧失败信息](failure-recheck-succeeded.png)。图中任务和费用为模拟数据。

主要命令：`pnpm typecheck`、各工作区包的 `test`、`pnpm test:maintenance`、`pnpm lint`、`pnpm --filter @super-canvas/desktop-ui build`，以及 renderer 目录下的 `pnpm exec playwright test --output=test-results-failure-recheck-final --reporter=list`。

本轮不打包、安装或发布桌面版本，已有未提交修改均保留。
