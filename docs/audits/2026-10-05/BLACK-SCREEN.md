# 桌面黑屏排查与恢复

## 已确认的现场情况

- 故障发生在本机已安装的 Windows 版，实际可执行文件版本为 **0.2.52**。当时线上最新版本为 0.2.54，本机尚未完成升级。
- 窗口存在，内容区只有深色背景。Windows 进程清单中有主进程、GPU 进程及 utility 进程，**没有 renderer 进程**；本地 Node 服务仍监听原端口。
- 本地 `desktop.log` 只有后端启动成功记录。旧版没有记录 `render-process-gone`，相关 Windows 应用事件中也未找到可用的退出原因证据。
- 安装包首页引用的 19 个 JS/CSS 文件均存在。源码中的首页数据请求失败和 React 错误边界有可见提示，未发现可复现的整页隐藏条件。
- 普通刷新未恢复。检查已保存的生成记录没有进行中任务、资料文件十分钟内无新写入后，先备份并校验资料，再只重启失效实例。原端口上的主页、已有画布及更新提示恢复正常，renderer 进程重新出现。

**结论边界：**可以确认界面进程已退出、旧版缺少恢复机制，不能从现有证据进一步认定是 GPU、内存不足、系统结束进程或某个具体渲染错误。重启后在原有 GPU 设置下可正常绘制，也不足以证明某类底层故障永远不会发生。

## 修复范围

- 监听界面退出、主框架加载失败、子进程退出及窗口无响应事件，记录脱敏诊断。
- 界面进程退出后有限自动重载；后台服务保持运行，不重新提交生成任务。
- 连续失败显示可重试的启动错误页，错误页失效时使用原生错误对话框。
- 页面加载失败后的重试复用仍在运行的本地服务。
- 保留退出前任务、后台写入和资料持久化检查，并处理渲染进程已经不存在的情况。

采用 Electron 官方 [render-process-gone 事件](https://www.electronjs.org/docs/latest/api/web-contents#event-render-process-gone)记录渲染进程异常退出；在隔离测试实例中用 [forcefullyCrashRenderer](https://www.electronjs.org/docs/latest/api/web-contents#contentsforcefullycrashrenderer)模拟同类故障，验证恢复行为。

## 验收改进

此前完整 smoke 使用 `--disable-gpu` 和 `offscreen: true`，且已有资料重启阶段只检查 URL 和 API，未检查主页实际显示。这些检查不能覆盖普通窗口的全部启动路径。

本次增加独立的可见窗口验收：正常 GPU 参数、`offscreen: false`、独立临时资料库，验证首次启动、已有资料重启、DOM 可见性及 Electron 合成后的图像不是纯黑。模拟渲染进程退出后核对恢复画面和后台服务连续性。原有完整 smoke 也补充重启后的页面异常收集和绘制检查。

最终本地验收结果：

- 桌面回归 **58/58** 通过，其中新增恢复与退出边界专项 **17/17**，独立审查再次运行专项也全部通过。
- 清理维护边界 **12/12** 通过。
- 最终打包版完整 smoke **25 项**通过，包括已有资料重启、页面无异常、项目列表与 API 一致。
- 最终打包版普通窗口 smoke **4 组**检查通过：首次启动、已有资料重启、强制 renderer 崩溃后恢复、页面异常检查。
- 普通窗口三阶段均启用正常 GPU 合成、可见且非 offscreen；原生截图 1424 × 921，均有明确文字及已加载的项目卡片，项目加载状态已结束且无错误提示。
- 故障注入后 renderer PID 改变，Node 后台 PID、进程创建时间、运行端口及资料路径保持不变。恢复前后两个测试项目的 ID、标题与页面列表一致。

独立审查复现并修复了恢复预算被慢失败重置、旧退出请求成功或失败晚到影响新退出、解除排空失败时待恢复页面被挂起的边界情况；相关回归均先复现失败再验证修复。

本地验收日志保存在 `.release-stage/*v0.2.55*.log`，原生截图和结构化报告在 `apps/desktop/release/smoke*`。CI 和发布流程均新增普通窗口检查及截图报告保留。所有故障注入仅对隔离测试实例执行，不操作真实用户窗口或发起付费生成。
