## 已确认的故障

最新失败任务 `0ad40b8f-0959-477f-b0ff-3f0196ba26ac` 使用本机传输，约 98.8 秒后返回 `UND_ERR_SOCKET`，没有获得供应商任务编号。它不是之前云端 HTTP 524 修复路径上的任务。HTTP 524 的 16 字节 `error code: 524` 是错误文本，不能作为图片解码。

本机启用 FlClash TUN，系统 DNS 将供应商域名解析为 `198.18.0.0/15` 假 IP。普通本机 fetch 实际经虚拟网卡。绑定物理网卡、使用公共 DNS 真实地址并校验供应商域名证书时，We-AI 和 secure-skill 的 TLS 握手成功；另一个供应商物理直连失败而系统路由成功。因此不能统一强制绕过代理，也不能据一次成功断言所有断连根因均已确定。

## 行为变更

- 共用 HTTPS 连接器在发现 TUN 假 IP 时，自动发现物理网卡并尝试真实地址 TLS。成功后将同一个 socket 交给 HTTP 客户端；握手失败才退回系统路由。选路发生在发送请求、提示词、密钥之前，已发送的收费请求不会换路重发。
- 明确配置的 HTTP/HTTPS 代理优先；无效代理报错，不能静默改成直连。证书校验和 SNI 保持开启。公共 DNS 查询仅包含供应商域名。
- OpenAI/We-AI 和 REST 图片生成、图片编辑默认没有应用截止时间；Undici 的 header/body 定时器也同步关闭。TCP keepalive 为 30 秒，但不将其视为供应商永不断连的保证。
- 旧预设保存的 `requestTimeoutMs` 只控制元数据/单次轮询，不再截断图片提交。若有确切需要，专用 `imageSubmitTimeoutMs` 可以显式设置图片期限，默认 0。测试或调用方显式传入的适配器预算仍有效。
- 已有任务编号的非 CLI 图片任务不再因 240 次轮询而停止；可重试的查询网络错误、限流和服务器错误持续退避重查。明确失败、鉴权错误以及手动取消仍会终止等待。恢复过程不重复提交生成请求。
- Corel 直接生成入口使用相同的图片查询规则；供应商图片核验不再在十分钟后放弃已创建任务。临时查询故障只重查原任务，CLI 和视频策略保持原样。
- 提交继承运行取消信号。进程退出的可选信号保留可恢复的任务状态；生产桌面仍通过已有退出保护等待本机活动任务，未增加主动切断同步请求的退出行为。
- 网络错误保存耗时、等待响应头/读取响应体阶段、已接收字节数、错误码等无敏感信息的诊断字段。
