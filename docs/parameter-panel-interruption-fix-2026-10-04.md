# 参数面板间歇无法下拉或滚动修复

模型与参数面板可能在框选中断后无法打开下拉菜单或滚动，重新打开面板可能暂时恢复。本报告保留可复现原因、修复和隔离测试，不包含本机安装或个人资料核对记录。

## 复现与原因

隔离浏览器中复现了阻塞：Ctrl 框选被 `pointercancel` 或窗口失焦中断时，React Flow 留下 `userSelectionActive` 与 `userSelectionRect`。活动框选矩形层级为 6，高于参数面板所在 viewport 的 4，且原本接收鼠标事件。旧实现中矩形在中断后持续存在，遮挡点击和滚动。

新增供应商、关闭设置、同时打开两个面板的常规流程可以通过测试。现有证据支持框选中断造成阻塞，未证明供应商目录本身会禁用面板。

## 修复

- 活动框选的纯视觉矩形不接收点击与滚轮事件。
- 指针取消、窗口失焦或捕获丢失后的外部释放结束框选，保留已选节点。
- 转发结束手势以停止边缘自动平移，消费遗留选择点击，避免恢复后的第一次模型菜单点击被吞掉。

源码位于 `apps/desktop/renderer/components/canvas-app.tsx` 与 `apps/desktop/renderer/app/globals.css`。

## 隔离验证

`apps/desktop/renderer/e2e/canvas-panel-after-supplier.spec.ts`覆盖新增供应商后的两个面板、异步目录刷新、鼠标打开原生下拉、模型选择、内层滚动，以及取消、失焦、捕获先丢失的恢复。

中断检查在后续鼠标松开之前执行，避免普通 pointerup 掩盖问题；失焦场景验证边缘自动平移停止。测试使用隔离数据库、虚假 Key 与 `.invalid` 地址，拒绝全部生成提交，不产生付费生图请求。

独立构建的 13 项浏览器回归通过，未跳过或重试，未记录 JavaScript 错误。覆盖四项新增供应商及中断恢复、四项既有面板交互、四项供应商切换、一项缩放/滚动稳定性；同一构建的四项失败生成及多选回归亦通过。

TypeScript、生产构建、相关 ESLint、Windows unpacked 打包与 release 校验通过。隔离 UI 验证说明交互修复有效，不代表真实供应商付费生成已经验证。
