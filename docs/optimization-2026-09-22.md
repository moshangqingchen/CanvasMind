# 优化实施记录 · 2026-09-22

本轮围绕大画布交互、任务并发、模型请求、历史查询和素材落盘降低重复工作。以下记录源码实现与验收口径。数据库仍使用 JSON 文件，没有实施 SQLite 迁移，也没有新增统一任务中心。

## 已落地的改进

| 范围 | 行为与默认值 |
| --- | --- |
| 画布保存 | 拖动、缩放节点尺寸时只保留最新图引用，每 **400 ms** 最多生成一次保存检查点；手势结束生成最终检查点。手动保存、离开画布、退出等保存屏障继续冲刷待保存内容。 |
| 图片预览 | 根据节点屏幕尺寸、画布缩放、设备像素比和节点内部缩放选择 **160 / 640 / 1200 / 2400 / 3840 px**；等待 **200 ms** 稳定后切换，升档与降档使用不同边界，避免临界尺寸反复请求。结果节点不会因多选整体升到最大预览。 |
| 运行调度 | 就绪的独立节点允许并行，默认每任务 **2**、全局 **4**、每供应商协议 **2**、每连接 **2**；一次领取全部资源配额，避免嵌套锁。相同仓库实例共享额度和单运行执行者租约；取消立即移除等待额度的任务。DAG 依赖、失败传播和取消状态仍决定后续节点是否可执行。 |
| 历史查询 | 按运行、画布及节点建立内存索引，缓存最近成功结果；导入、更新、删除时维护索引。落盘格式保持兼容。 |
| 素材归档 | HTTP 输出通过有大小限制的流写入临时文件，计算 SHA-256 后发布对象与元数据；项目文件支持流式复制。按运行、节点、输出序号生成稳定素材 ID，复用通过完整性检查的既有对象，减少重复下载。 |
| 智能体上下文 | 单次请求的系统文本与消息合计最多 **64,000 字符**，其中系统文本最多 **16,000 字符**；正常 API 路径保留当前用户请求，优先纳入最新观察。工具观察先生成可序列化摘要，再按上下文预算保留；目录与画布默认每页 **15** 项、最多 **30** 项，连线和素材引用可独立续页查询。此预算不含附件及工具 schema，不是整轮所有调用的总量，也不冒充供应商的精确 Token 限制。 |
| 调用统计与取消 | 主模型、视觉助手、结构修复和导演调用分别记录耗时、状态及供应商实际返回的 usage，不推算价格。统计不进入用户对话或模型历史。导演断开连接时向适配器传播取消信号；取消后不启动修复请求，写回复前检查并丢弃迟到结果，保留已保存的用户提问。已经进入提交的回复不回滚，也不能据此保证远端停止计算。 |
| 模型库存 | 画布、导演和扫描流程共用 `provider-model-inventory` 服务，API 路由仅转发。导演读取目录最多 **4** 个连接并行；全量供应商刷新最多 **2** 个供应商并行，整批前后各读取一次完整连接列表。 |
| 桌面依赖 | 桌面运行依赖使用冻结的 `runtime-package-lock.json`，打包阶段执行 `npm ci`，构建前检查依赖清单与锁文件一致性；只有显式 `pnpm desktop:lock` 更新锁文件。 |
| 开发启动 | `pnpm dev` 启动 Electron、Next 热更新和六个共享包编译监听器，使用独立的 `SuperCanvasDesktopDevelopment` 资料目录；关闭开发窗口后退出所属服务。生产构建预览保留为 `pnpm desktop:dev:production`。 |

运行并发可分别通过 `RUNTIME_RUN_CONCURRENCY`、`RUNTIME_GLOBAL_CONCURRENCY`、`RUNTIME_PROVIDER_CONCURRENCY`、`RUNTIME_CONNECTION_CONCURRENCY` 配置。有效值为 1–64 的整数；无效值回到默认值。调大配置前应确认供应商的实际限流和本机资源。

## 保留的兼容保护

- 保存仍检查画布 revision，冲突时不覆盖新编辑；本地草稿、撤销及退出保存屏障继续生效，400 ms 合并不用于省略最终保存。
- 401/403 和确认空目录仍是权威结果；临时网络失败可保留旧库存，但不得把旧快照标成刷新成功。连接版本、扫描 requestId、客户端 epoch 和密钥隔离继续阻止旧结果覆盖新配置。
- 媒体生成仍经过方案确认、预检和幂等请求 ID；预算压缩没有扩大工具权限，也没有自动提交付费核验。视觉观察缓存按素材指纹匹配。
- 素材下载保留协议、DNS、逐跳重定向和大小检查；临时文件失败时清理。下载超时约束网络及源迭代过程，不宣称是涵盖随后所有磁盘提交的硬截止时间。
- 新流式接口保留 `get` / `put` 兼容路径；原图导出继续使用原始素材，不导出预览缩略图。

## 可重跑的性能检查

在仓库根目录执行：

```powershell
pnpm benchmark:repository
pnpm --filter @super-canvas/desktop-ui exec playwright test e2e/canvas-performance.spec.ts
```

画布检查覆盖 50 / 200 / 500 节点的提示词场景和混合图片场景，分别测量拖动、缩放、多选拖动的帧间隔，输出 `performance.json`。默认 P95 回归上限如下，属于宽松的回归门槛，不代表稳定 60 FPS：

| 节点数 | 提示词场景 | 混合图片场景 |
| ---: | ---: | ---: |
| 50 | 33.4 ms | 41.75 ms |
| 200 | 66.7 ms | 83.375 ms |
| 500 | 120 ms | 150 ms |

可用 `CANVAS_PERF_P95_PROMPT_500_MS` 等 `CANVAS_PERF_P95_<PROMPT或MIXED>_<节点数>_MS` 环境变量设置测试机阈值。`CANVAS_PERF_PROFILE_ONLY=1` 只采样、不执行性能阈值断言，不能计作门槛通过；`CANVAS_CPU_PROFILE=1` 可采集 200 节点缩放的 CPU profile。默认关闭 trace、截图和视频，避免测量操作自身显著干扰帧时间。

本次 Windows 本机生产构建实测 P95 如下，**18 组均通过默认门槛**。完整采样见 [canvas-performance.json](benchmarks/optimization-2026-09-22/canvas-performance.json)。

| 场景 | 节点数 | 单节点拖动 | 缩放 | 多选拖动 |
| --- | ---: | ---: | ---: | ---: |
| 提示词 | 50 | 5.7 ms | 11.2 ms | 11.1 ms |
| 提示词 | 200 | 22.4 ms | 66.7 ms | 11.2 ms |
| 提示词 | 500 | 77.8 ms | 116.6 ms | 27.8 ms |
| 混合图片 | 50 | 6.0 ms | 27.8 ms | 11.1 ms |
| 混合图片 | 200 | 38.7 ms | 72.3 ms | 61.1 ms |
| 混合图片 | 500 | 55.6 ms | 116.7 ms | 61.2 ms |

每组记录 48–251 个帧间隔。混合场景使用 8 张合成的 2048×1536 图片，并检查全选不会把全部图片升到 3840 px。500 节点仍出现明显长帧，提示词缩放最大约 327 ms；本次没有相同负载、相同环境的旧版本对照，不能据此承诺整体提速比例或稳定 60 FPS。

仓库查询基准由 `scripts/benchmark-repository.mjs` 生成隔离的合成数据，不打开个人数据库。本次初始样本如下：

| 节点运行历史记录数 | 列表查询 P95：旧算法 → 索引 | 最近成功查询 P95：旧算法 → 索引 | 完整 JSON 写入 P95 |
| ---: | ---: | ---: | ---: |
| 1,000 | 0.044 → 0.025 ms | 0.026 → 0.005 ms | 3.163 ms |
| 10,000 | 0.086 → 0.023 ms | 0.180 → 0.005 ms | 9.464 ms |
| 50,000 | 0.453 → 0.026 ms | 0.864 → 0.002 ms | 49.956 ms |

这里的基线是等价旧查询算法，并非整机或应用版本的前后对照；查询采样 100 次，写入采样 5 次。数据说明索引减少了随历史量增长的扫描开销，但全量 JSON 写入仍随数据量增加，不能据此声称数据库写入瓶颈已经消失。
