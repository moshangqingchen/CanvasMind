# 新分组 4K 核验与连接隔离修复

## 本次问题

辰途 API 的 `image2.5全参` 分组新增后，`gpt-image-2.5-sunburst` 菜单只有 1K。实际原因有两项：

- 能力展示在缺少说明时仅显示假设的 1K，隐藏了自动核验已经选定的 4K。
- 自动接入已经创建 Flare、Sunburst 的 4K/max 请求，但供应商级队列仍被 2026-09-21 另一个分组的 Key 鉴权失败暂停，因此两个新请求一直没有提交。

不存在供应商明确声明该新分组只支持 1K 的证据。

## 实现

`supplier-capabilities.ts` 将未知能力的最高候选档位及已排队档位展示为待核验，沿用现有 4K 优先规则。明确排除、固定分辨率型号、原生参数枚举仍有效；未实测的档位不标记为实测支持。

`supplier-verification-service.ts` 将提交阶段的 401/403 限制到当前连接与凭据配置。保留原请求，停止该连接的剩余测试，继续其他分组。新 Key 接入可解除其旧凭据限制。旧自动鉴权暂停只在证据一致且无其他未决、已扣费失败或手动暂停时迁移；手动与扣费暂停不被自动解除。

增加 `run-case` 操作执行指定的尚未提交核验任务，使用原请求 ID、原参数、原归档流程；持久化提交占用保证不会重复提交同一任务。GPT 生图协议与传输流程未修改。
