# 海报、宣传图与活动物料

在 App 的画布左侧点击「设计」打开「平面设计」工作台。

## 制作新设计

也可以直接在「客户原文」粘贴客户的一整段需求，或添加最多 4 张客户截图、文案图片，点击「自动提取客户内容」。提取使用 API 设置中已配置的智能体模型；图片需要支持图片输入的模型。只有点击提取按钮才会调用模型，费用按该连接的供应商计算。

图片内容提取使用统一智能体目录中可用且支持图片输入的模型。列表为空时，在「供应商与模型」检查分组 Key、模型目录与协议，刷新目录后重新选择；不再需要独立智能体 Key 或旧版能力勾选。

客户原文按原样保存，并完整写入每个设计方案的提示词，不会用提取摘要替换。提取只补充尚未填写的标题、时间、地点等字段，已有手写内容不被覆盖。纯文字需求也可直接放入画布，不必先提取或填写主标题。单次原文最多 60000 个字符，超过时提示处理，不会自动截断。

图片的识别文字按图片逐张展示，可对照原图补全修改，确认全部文字完整后再创建设计。识别可能遗漏或误读数字、联系方式等内容，请逐字核对。客户原图与核对后的完整转录会随设计保存，转录全文进入提示词；只有另外选作参考图时，客户图片才参与画面风格或主体参考。

勾选「自定义画面比例」可以填写宽、高和安全距离。例如宽 210、高 289、安全距离 7，提示词明确要求：**画面比例为 210:289，主要元素以及文字必须在居中的 203:282 范围之内。**这里安全距离按总宽、总高各减 7 计算，居中后每边 3.5，与输入比例数值使用同一单位；背景可以延伸到画面边缘。

模型声明支持该比例时使用对应参数。模型没有声明精确支持时，界面会说明实际输出仍受模型尺寸限制，比例与安全范围作为构图要求写入提示词；210:289 不会被误传为 210×289 像素。交付前仍需核对实际尺寸、安全范围和文字，提示词无法保证模型完全精确执行。

选择「活动海报」「宣传图」或「活动物料」，填写主标题、副标题、正文，以及需要出现的活动时间、地点和行动文案。留空的内容不会被要求自动补写。填写品牌名称、配色和视觉风格，可保存为本机品牌预设，下次直接加载。

参考图可从图片资料库选择，也可直接上传。为每张图指定用途：主体素材、品牌标志、风格参考或待修改原图。图片以固定素材 ID 接入生成流程，不会覆盖原图。最多使用 4 张，同时受所选模型的参考图能力限制。

选择已经配置的 Image 2 系列模型，再选择该模型支持的尺寸与 1–3 个版式方案。尺寸数量乘以方案数量最多为 6 张。不同版式使用不同构图要求；跨尺寸保持相同文案与品牌要求，具体一致性由模型输出决定。

- 「放入画布」创建可编辑的设计节点，不提交生成。
- 「生成设计」创建节点并逐个提交本次设计任务，不运行画布中的其他节点。每个设计节点请求一张图片，生成费用按所选供应商计算。

没有可用模型时，点击 API 设置配置并扫描图片模型。尺寸来自已配置模型的能力信息，不会自动换成其他模型或提交不支持的预设尺寸。任务失败会显示在画布结果节点中，可修改后再运行。

## 修改已有设计

切换至修改模式，选择一张待修改原图，并填写换文案、换背景、调整配色等要求。也可以先选中画布中的图片，再打开「平面设计」，原图会自动带入。

选中由工作台创建的设计节点后，再次打开「平面设计」，可以复用原来的结构化需求。新任务会创建新节点，保留原设计和原图片。

## 草稿与交付

未提交的表单按画布保存到本机草稿，关闭后重新打开可继续填写。品牌预设保存在本机；创建节点后，设计需求随画布节点保存。品牌预设和未提交的表单草稿不随项目包迁移。

文字、Logo、版面元素与最终图片均由所选图片模型生成。工作台不进行本地文字叠加、图片合成或二维码绘制，也不生成可编辑的文字图层、矢量源文件或印刷分色文件。成图后可进入「历史生成」比稿、记录修改意见和标记定稿；交付前需核对成图文字及输出尺寸。

## 常用方案、费用与交付

首页可按「做活动海报」「修改客户原图」「制作多尺寸物料」直接进入工作台。表单中的「我的常用方案」可保存当前文案结构、品牌、参考图用途、尺寸及模型选择；同名保存会更新方案。套用后核对并替换客户内容，不会自动生成，缺失素材和不可用模型须重新选择。

「导出方案与素材」创建完整项目包，可从项目菜单导入，在新画布选中设计节点后打开平面设计继续编辑。它包含当前表单中的品牌要求和参考素材，不包含整份本机品牌库或其他未提交草稿。

生成按钮旁显示各张设计的价格与整批估算，按当前型号和参数计算。按用量计费、参数无匹配价及仅有旧实测样本时，明确显示费用待确认；可计算金额保留供应商原币种，不能视为保证上限。

成图后打开「历史生成」，默认查看当前项目。定稿图片的详情中展开「交付检查与导出」，逐项核对文字、完整性、实际尺寸和最终版本，再导出原图与交付记录。检查记录保存在导出的 delivery.json 中；图片保持原始字节，不生成本地文字图层或合成内容。
